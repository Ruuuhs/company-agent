# 仮想チーム — Claude Code マルチエージェント組織

Claude Code の Agent tool を活用し、**10部門・24エージェント**で構成された仮想会社組織です。代表（あなた）が司令塔（CLAUDE.md）に指示を出すと、適切なエージェントが自律的に動き、実務レベルのアウトプットを生成します。

---

## どういう仕組みか

```
あなた（代表）
    ↓ 指示
CLAUDE.md（司令塔）
    ↓ タスクを解析してルーティング
各部門エージェント（agents/）
    ↓ 専門領域で実務を担当
アウトプット（提案書・台本・分析レポート etc.）
```

**司令塔（CLAUDE.md）は3つのことしかしません：**
1. **プランニング** — 曖昧な指示を要件に落とす
2. **ルーティング** — 「これは誰の仕事か」を判断してエージェントを起動
3. **統合** — 各エージェントの結果をまとめて報告

司令塔自身はアウトプットを作りません。必ずエージェントに仕事を振ります。

## 使い方

### スラッシュコマンドで部門を呼び出す

```
/strategy   次期3ヶ年計画の骨子を作りたい
/content    競合チャンネルとの差別化を軸にYouTube企画を3本出して
/marketing  新サービスのローンチに向けてSNS投稿とプレスリリースを準備したい
/sales      ○○社との商談議事録をまとめて提案書を作って
/research   AIエージェント市場の最新トレンドと競合状況を調査して
/data       先月のKPIをまとめてボトルネックを分析して
/hr         エンジニア採用の求人票と面接評価シートを作って
/management 先月の経費をチェックして、この業務委託契約のリスクも確認して
/ma         この会社の事業価値を算定してほしい
/business-dev 既存コースの価格改定を検討したい。収益モデルも見直したい
```

### 直接エージェントを指定することもできる

```
agents/04-マーケティング部/コピーライター.md のコピーライターとして、
新サービスのLPキャッチコピーを3案作成してください。
```

### 複合タスクは自動で並列処理される

司令塔が「これは複数部門の仕事」と判断した場合、関連エージェントを同時起動して並列処理します。

**例：「新規コースのローンチ準備をまるごとやって」**

```
事業企画者（コース設計）
    ↓ 並列起動
コピーライター（LP）
    ↓ 並列起動
SNSライター（告知投稿）
    ↓ 並列起動
PRライター（プレスリリース）
    ↓ 統合
司令塔がまとめて報告
```

## 設計思想

### 1. CLAUDE.md は軽量に保つ

司令塔（CLAUDE.md）には「誰に振るか」だけを書きます。業務の詳細ルール・テンプレート・禁止事項はすべて各エージェントファイルに移譲します。司令塔が肥大化するとルーティング精度が下がります。

### 2. エージェントファイルはシステムプロンプトとして書く

`agents/` 配下の各ファイルは、第三者視点のドキュメントではなく**直接指示形式（「あなたは〜です」）**で記述します。Claude Code がそのままロールとして読み込めるようにするためです。

各エージェントファイルには以下を含めます：

- 役割とミッション
- 専門領域と得意なこと
- 思考スタイル・口癖・判断軸
- 必ず守るルール
- 参照すべきガイドライン
- 他エージェントとの連携方法
- アウトプットテンプレート（Markdown コードブロック）
- 自己判断 OK／代表確認必須の判断基準表

### 3. 作る人と評価する人を分ける

同一エージェントに「作成」と「レビュー」を同時にさせると精度が下がります。台本ライターが書いた台本をビジュアルデザイナーが確認する、競合アナリストの分析を戦略立案者が統合するなど、役割を分けてチェックをかけます。

### 4. guidelines は育てるもの

`guidelines/` は最初から完璧である必要はありません。実際に使いながら「この判断基準が足りない」「この表現はブランドに合わない」と気づいたときに随時更新します。仮想チームの質はガイドラインの質に比例します。

### 5. 代表確認ラインを明確にする

各エージェントファイルには「自己判断 OK」と「代表確認必須」の境界線を明示しています。エージェントが自律的に動くほど、この境界線の設計が重要になります。`guidelines/escalation-rules.md` で共通基準を定め、各エージェントはそれを参照します。

## カスタマイズ方法

### 自社情報を設定する

まず以下の2ファイルを自社情報で埋めてください。全エージェントの動作の土台になります。

```
guidelines/company-overview.md   ← 会社名・事業内容・ターゲット顧客
guidelines/ceo-style-guide.md    ← 代表の口調・発信スタンス・禁止表現
```

### 新しいエージェントを追加する

1. `agents/XX-部門名/役職名.md` を作成（既存ファイルのフォーマットに倣う）
2. 該当部門のスラッシュコマンド（`.claude/commands/*.md`）にルーティングを追加
3. `guidelines/collaboration-protocol.md` に連携パターンを追記

### 不要な部門を削除する

1. 該当エージェントファイルを削除
2. `.claude/commands/` の該当コマンドファイルを削除
3. `CLAUDE.md` のルーティングテーブルから該当行を削除
