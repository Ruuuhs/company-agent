# 仮想チーム for Claude Code

Claude Code 上で動く「AI 社員チーム」のテンプレートです。
**10 部門・24 人の AI 社員**があなたの会社の実務を担当します。

> **クローンした直後は汎用テンプレートです。使いながら育てることで、あなたの会社専用のチームになっていきます。**

---

## これは何？

一言で言うと、**Claude Code に「会社組織」を持たせる仕組み**です。

通常の Claude は何でも答えてくれる万能アシスタントですが、このリポジトリを使うと Claude が**専門の担当者として動く**ようになります。

| 普通の Claude | このリポジトリを使った Claude |
|-------------|--------------------------|
| 何でも答えるが、深みが浅い | 担当者として深く・専門的に動く |
| 毎回ゼロから説明が必要 | 会社のルール・ブランド・方針を覚えている |
| 1人で全部やろうとする | 複数の担当者が同時に動いて効率化 |
| 使い続けても変化しない | **育てるほど自分の会社に馴染んでいく** |

---

## どんなことができるの？

Claude Code を開いて `/` からコマンドを打つだけで、専門の担当者が動き出します。

```
あなた: /research 競合のSES会社3社と自社の違いを整理したい。
        強み・弱み・単価帯・エンジニアの質で比較して。

→ 市場調査員・競合アナリストが動き出し、
  ・競合3社の比較表（単価帯・得意分野・採用スタイル・強み/弱み）
  ・自社のポジショニング分析
  ・差別化できる軸の提案
  をまとめたレポートを作成してくれる
```

```
あなた: /hr  エンジニアを3名採用したい。
            SES事業なので稼働率と収益への影響も踏まえた採用計画を立てたい。
            現在の稼働率は85%で、来期は案件が増える見込み。

→ 採用マネージャーが動き出し、
  ・稼働率・収益シミュレーション付きの採用計画
  ・市場需要に合わせた必要スキルセット定義
  ・求人票（SES特有の魅力訴求）
  ・面接評価シート（技術力 + 常駐適性）
  を作成してくれる
```

```
あなた: /sales  明日、株式会社○○との初回商談がある。
               相手は情報システム部の課長で、開発リソース不足が課題らしい。
               商談の進め方と事前準備を整理して。

→ 営業サポートが動き出し、
  ・想定される課題と切り口の仮説
  ・商談の進め方シナリオ
  ・事前に準備すべき資料リスト
  を出してくれる
```

## はじめ方

### Step 1. このリポジトリをクローンする

```bash
git clone https://github.com/Ruuuhs/company-agent.git
cd company-agent
```

> **クローンとは？** リポジトリ（ファイル一式）を自分のパソコンにコピーすることです。
> Claude Code のターミナル（画面下部の黒い入力欄）に上記を貼り付けて Enter を押してください。

### Step 2. Claude Code でこのフォルダを開く

Claude Code を起動し、クローンしたフォルダを開きます。

### Step 3. `/setup` で自社情報を入力する

チャット欄に `/setup` と打つと、**インタビュー形式で自社情報を入力できます。**
会社名・事業内容・代表のスタイル・ブランドカラーなどを質問に答えていくだけで、
必要なファイルが自動で書き込まれます。

```
/setup
```

> **自分でファイルを直接編集したい場合** は `guidelines/` フォルダ内のファイルを開いてください。
> 各ファイルに「何を書くか」の説明とサンプルが記載されています。

### Step 4. 試しに使ってみる

セットアップが終わったら、コマンドを打って動作確認してみましょう。

```
/research  SES市場の直近トレンドと、採用に影響しそうな動向を調査して
```

## 使いながら、自分好みに育てる

このチームは使い始めが完成形ではありません。
**使うたびに気になることが出てきたら、その場で育てていくのが正しい使い方です。**

### よくある「育て方」の例

```
担当者の口調が固すぎる
  → /edit-agent で「もっとフランクなトーンに変えて」と伝える

出力フォーマットが使いにくい
  → /edit-agent で「表ではなく箇条書きにして」と指示する

自社にない部門の担当者が邪魔
  → agents/ から不要なファイルを削除する

足りない役割がある
  → /add-agent で新しい担当者を追加する

会社の方針が変わった
  → /edit-agent または guidelines/ を直接編集して全員に反映
```

### カスタマイズ専用コマンド

| コマンド | 何をするか | いつ使うか |
|---------|----------|----------|
| `/setup` | 会社情報をインタビュー形式で入力。guidelines を自動書き込み | **最初に一回** |
| `/check` | 何が設定済みで未設定かを確認。次のアクションを提案 | 定期的に / 迷ったとき |
| `/add-agent` | 新しい AI 社員をウィザード形式で追加 | 足りない役割ができたとき |
| `/edit-agent` | 既存の AI 社員の動き方・出力・ルールを変更 | **動きが気になったらすぐ** |

> **コツ:** 「なんか違う」と感じたらすぐ `/edit-agent` を使うのが一番早いです。
> 試行錯誤しながら育てることで、チームが自分の会社にフィットしていきます。

## 業務コマンド一覧

チャット欄で `/` を入力すると、以下のコマンドが使えます。

| コマンド | 担当部門 | こんなときに使う |
|---------|---------|--------------|
| `/strategy` | 経営企画部 | 事業戦略・競合分析・会議の議事録 |
| `/business-dev` | 事業開発部 | 新規事業・価格設計・収益モデル |
| `/content` | コンテンツ制作部 | 台本・教材・コンテンツ企画 |
| `/marketing` | マーケティング部 | SNS投稿・プレスリリース・広告コピー・メルマガ |
| `/hr` | 人事部 | 採用・求人票・面接設計・オンボーディング |
| `/management` | 経営管理部 | 経費確認・予算管理・契約書チェック・法務リスク |
| `/research` | リサーチ部 | 市場調査・競合調査・AIトレンド・助成金情報 |
| `/data` | データ分析部 | KPI分析・ABテスト・数値レポート |
| `/sales` | 営業部 | 提案書・見積書・商談議事録・契約書 |
| `/ma` | M&A評価部 | 企業価値算定・デューデリジェンス・PMI計画 |

### 複数部門にまたがる仕事は自動で振り分けられる

大きなタスクは Claude が自動で複数の担当者に振り分けます。コマンドなしで話しかけてもOKです。

```
来月から新しい常駐案件に向けてエンジニア採用を強化したい。
求人票・面接設計・SNS告知・採用ページのコピーを全部準備したい。

→ Claude が自動で
  採用マネージャー・SNSライター・コピーライターを起動して並行作業
```

## AI 社員の一覧

### 01 経営企画部

| 担当者 | 仕事内容 |
|-------|---------|
| 戦略立案者 | 中長期の事業戦略を立案。「感情ではなくデータと構造で語る」がモットー。複数の選択肢と推奨案を必ず提示する |
| 競合アナリスト | 競合他社をデータで分析し「自社がどこで戦うべきか」を明確にする。事実・考察・示唆を分けて報告する |
| 議事録担当 | 会議の記録・アクション管理を担当。「誰が・何を・いつまでに」が1分で読める議事録を作る |

### 02 事業開発部

| 担当者 | 仕事内容 |
|-------|---------|
| 事業企画者 | 新規事業・新サービスの企画立案。「小さく始めてデータで育てる」思想で動く |
| 収益設計者 | 価格設定・収益モデル設計・外部パートナーとの連携スキームを構築する |

### 03 コンテンツ制作部

| 担当者 | 仕事内容 |
|-------|---------|
| YouTube企画者 | 「誰に・何を・なぜ今」の3軸で企画書を作成。競合分析・サムネイルコンセプトまで含む |
| 台本ライター | 代表の話し方を再現した台本を執筆。「最初の15秒で離脱を防げるか」を常に問いかける |
| ビジュアルデザイナー | サムネイル指示書・動画編集指示書を作成。「スマホの小さい画面で1秒で伝わるか」を基準にする |
| 教材設計者 | オンライン教材・カリキュラムを設計。「教えた」ではなく「使えるスキルになったか」を重視する |

### 04 マーケティング部

| 担当者 | 仕事内容 |
|-------|---------|
| SNSライター | X（旧Twitter）の投稿文案を作成。エンゲージメントの高い投稿パターンを熟知している |
| PRライター | プレスリリースを作成。「記者がこれを記事にしたいか？」の目線で書く |
| コピーライター | LP・広告・バナーのコピーを担当。必ず3案以上・訴求軸違いで提案する |
| CRMマネージャー | メルマガ・LINEのシナリオ設計。「受け取って嬉しい・読んで行動したくなる」を目指す |

### 05 人事部

| 担当者 | 仕事内容 |
|-------|---------|
| 採用マネージャー | 求人票・面接設計・採用戦略を担当。SES事業では稼働率・案件充足率への影響を踏まえた採用計画が重要で、必要スキルセットの市場需要との整合も考慮する |
| 組織デザイナー | 組織設計・オンボーディングプログラムを担当。新メンバーが早期に活躍できる環境を整える |

### 06 経営管理部

| 担当者 | 仕事内容 |
|-------|---------|
| 財務コントローラー | 経費チェック・予算管理・月次の予実対比を担当。「この支出、事業への貢献は？」を常に問う |
| 法務チェッカー | 契約書・利用規約の法的リスクをチェック。リスクを「高・中・低」で分類して対策をセットで提示する |

### 07 リサーチ部

| 担当者 | 仕事内容 |
|-------|---------|
| 市場調査員 | 市場規模・競合・顧客の声（VOC）を調査。「ソースはどこ？」「いつのデータ？」を常に確認する |
| トレンドウォッチャー | AIや技術の最新動向・助成金・政策変更を監視。自社事業への影響を早期に把握する |

### 08 データ分析部

| 担当者 | 仕事内容 |
|-------|---------|
| KPIアナリスト | 売上・稼働率などのKPIを分析。ABテストの設計・結果解釈も担当。「その数字、先月比でどう？」が口癖 |

### 09 営業部

| 担当者 | 仕事内容 |
|-------|---------|
| 営業サポート | 商談議事録・提案書・見積書を作成。「顧客の本当の懸念は何か？」を起点に提案を構成する |
| 契約ライター | 業務委託契約書・NDAなどを作成。取引を法的に適切な形で締結して会社を守る |

### 10 M&A評価部

| 担当者 | 仕事内容 |
|-------|---------|
| 案件アナリスト | M&A候補企業の調査・企業価値算定・デューデリジェンスを担当。感覚ではなく数字で評価する |
| PMIプランナー | 買収後の統合計画を立案。「Day1から1年後まで」のマイルストーンをシナジー定量化とともに設計する |

## フォルダの説明

| フォルダ / ファイル | 何が入っているか | カスタマイズ方法 |
|------------------|--------------|--------------|
| `CLAUDE.md` | 司令塔の定義。Claude が誰に仕事を振るかを判断するルールが書いてある | 部門を追加・削除したら編集する |
| `agents/` | AI 社員の指示書。仕事内容・ルール・出力テンプレートが書いてある | `/edit-agent` または直接編集 |
| `guidelines/` | 全員共通のマニュアル。会社の方針・ブランド・ルールをここに集約 | `/setup` または直接編集 |
| `templates/` | 書類のひな形。提案書・見積書など 13 種類 | 直接編集して自社フォーマットに |
| `.claude/commands/` | スラッシュコマンドの定義 | 部門を追加したときに編集する |
| `docs/` | このプロジェクトの背景と設計思想 | 参照用 |

## よくある質問

**Q. プログラミングの知識がなくても使えますか？**
A. 使えます。ファイルはすべて日本語で書かれたテキストファイルです。Claude Code の使い方（チャットで話しかける）を知っていれば十分です。

**Q. 担当者の動き方が気に入らないときはどうすれば？**
A. `/edit-agent` を使ってください。「もっと短く」「表ではなく箇条書きで」「この表現は使わないで」など、気になったことを伝えるだけで担当者の設定を変更できます。使いながら少しずつ育てていくのが正しい使い方です。

**Q. 自社に合わない部門は削除できますか？**
A. できます。`agents/` フォルダから不要なファイルを削除し、`.claude/commands/` の該当コマンドファイルも削除してください。`CLAUDE.md` のルーティングテーブルからも該当行を消せば完了です。

**Q. 担当者が勝手に重要な決定をすることはありますか？**
A. ありません。各担当者には「自分で判断してよいこと」と「代表に確認が必要なこと」が明示されています。契約の締結・10%超の値引き・プレスリリースの公開などは必ず確認を求めます。

**Q. 担当者同士が勝手にやり取りしてループしませんか？**
A. しません。すべての指示は Claude（司令塔）を経由します。担当者同士が直接やり取りする設計にはなっていません。
