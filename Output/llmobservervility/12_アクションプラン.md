# LLM Observability 受託事業 — 優先アクションプラン

**作成日**: 2026-04-24
**対象期間**: 2026年4月〜2027年9月（18ヶ月）
**フェーズ構成**: Phase 0（準備）→ Phase 1（官公庁特化）→ Phase 2（金融・製造拡張）

---

## 全体マップ：何をいつやるか

```
Phase 0（今〜1ヶ月）  Phase 1（1〜6ヶ月）     Phase 2（6〜18ヶ月）
─────────────────────────────────────────────────────────────────
OSS評価・技術基盤    → 初案件獲得・実績作り  → 複数業種展開・継続収益化

```

## Phase 0：準備（今すぐ〜1ヶ月以内）

### 🔧 A. OSSツール評価（最優先・最初の2週間）

参入事業の技術基盤になるツールを実際に触って評価する。評価結果がサービス提案の根拠になる。

#### 評価すべきOSSスタック

| ツール | 役割 | 評価すること | 公式サイト |
|--------|------|------------|-----------|
| **Langfuse** | LLMトレーシング・評価の中核 | オンプレ構築の難易度、ClickHouse連携、日本語対応 | https://langfuse.com |
| **Arize Phoenix** | OSS評価・トレーシング | エンタープライズ利用の制限、オフライン動作可否 | https://phoenix.arize.com |
| **OpenTelemetry GenAI SIG** | トレーシング標準 | 現在のExperimental→Stable移行状況、Langfuse/Datadogとの互換性 | https://opentelemetry.io/docs/specs/semconv/gen-ai/ |
| **ClickHouse** | LLMログの大規模ストレージ | オンプレ構築コスト、Langfuseとの連携方法 | https://clickhouse.com |
| **Grafana** | ダッシュボード・可視化 | LLMメトリクス表示のカスタマイズ性 | https://grafana.com |

#### 評価の具体的アクション

- [ ] **ローカル環境でLangfuse + ClickHouseをDockerで動かす**（1〜2日）
- [ ] **サンプルLLMアプリ（OpenAI GPT-4o使用）にLangfuseのSDKを組み込み、トレースを確認する**（1日）
- [ ] **OpenTelemetry GenAI SIGのExperimental仕様を読み、Langfuseとの相性を確認する**（1日）
- [ ] **Arize Phoenixをローカルで起動し、Langfuseとの機能差を比較する**（1日）
- [ ] **OSSスタックの構成図（Mermaid/Draw.io）を作成して資料化する**（1日）

#### 参考リソース
- Langfuse セルフホストドキュメント：https://langfuse.com/docs/deployment/self-host
- Langfuse + ClickHouseスタックガイド：https://langfuse.com/docs/deployment/self-host-clickhouse

### 📋 B. 規制要件の把握（最初の2週間）

営業トークと提案書の根拠になる。まず「何が求められているか」を自分の言葉で説明できるレベルに理解する。

#### DS-920（デジタル庁・官公庁向け）

**なぜ最優先か**：すでに施行済みの政府調達要件。「対応できる業者」として名乗り出るだけで引き合いが来る可能性がある。

| アクション | 詳細 | 出力物 |
|-----------|------|-------|
| DS-920の全文を読む | デジタル庁のガイドライン原文を確認 | LLM Observabilityに関係する要件チェックリスト |
| チェックシートの「AI関連」項目を抽出 | 「有害情報の出力制御」「ログ保存」「ハルシネーション対策」の具体要件を特定 | 要件マトリクス（要件 × 対応可能なOSSツール） |

- [ ] DS-920ガイドライン原文を入手・読む
  - 参考：デジタル庁クラウドサービス調達基準 https://www.digital.go.jp/policies/cloudservice-procurement/
- [ ] LLM Observabilityに関係する項目を抜き出してスプレッドシートにまとめる（30項目目安）
- [ ] 各要件に対して「Langfuse で対応できるか？」を○/△/×で評価する

#### FISC安全対策基準 第13版（金融機関向け）

**なぜ重要か**：2025年3月施行。AI安全対策基準が新設された。金融案件の営業で「FISC第13版の要件を知っている」だけで信頼度が上がる。

| アクション | 詳細 | 出力物 |
|-----------|------|-------|
| FISC第13版のAI安全対策基準項目を入手 | FISC会員でなくても要約は公開資料で確認可能 | AI安全対策の4カテゴリ（方針策定・運用管理・安全対策・教育）の詳細リスト |
| 関連する管理項目をObservabilityに紐付ける | どのFISC要件がどのObservability機能で対応できるかを整理 | FISC対応マトリクス |

- [ ] FISC公式サイトでAI安全対策基準の概要を確認：https://www.fisc.or.jp
- [ ] 二次情報記事（金融IT専門メディア）でポイントを把握する
- [ ] 「FISC第13版 × Langfuse導入でここが対応できる」という1枚の整理表を作成

#### ISMAP（官公庁・クラウド調達要件）

**なぜ準備が必要か**：2027年3月のISMAP管理基準改訂でAI固有要件が追加予定。今から動けば先行者になれる。

| アクション | 詳細 |
|-----------|------|
| ISMAPポータルで現行管理基準を確認 | https://www.ismap.go.jp |
| 生成AIに関する留意点を読む | https://www.ismap.go.jp/csm?id=kb_article_view&sysparm_article=KB0011070 |
| ISMAP-LIU登録サービスリストで競合状況を把握 | Langfuse自己ホスト版のISMAP対応可否を確認 |

- [ ] ISMAPポータルで現行管理基準（PDF）をダウンロードして読む
- [ ] 2027年改訂に向けたパブコメ内容（2025年9月版）を確認する
- [ ] 「Langfuse OSSをISMAP登録クラウド（AWS/Azure）上に構築する際の対応方針」をメモにまとめる

### 🔍 C. 市場・顧客調査（最初の1ヶ月）

実際に「困っているか」を確認する。調査なしで事業を進めると方向性がずれるリスクがある。

#### ターゲット顧客へのヒアリング（5〜10社）

**ヒアリング対象の優先順位**

| 優先度 | 対象 | 選定理由 |
|--------|------|--------|
| ◎ 最優先 | 官公庁IT担当者・政府関連機関のAI推進担当 | DS-920施行済み。源内実証開始（8月）前が最適タイミング |
| ○ 優先 | 中堅IT企業のCTO・技術責任者（LLM本番運用済み） | 課題が顕在化しており、意思決定が速い |
| ○ 優先 | 金融機関の情報システム部門（LLM検討・PoC中） | 単価が大きい。時間はかかるが先行アプローチが重要 |

**ヒアリングで聞くこと**

1. 現在、LLMは本番稼働しているか？どのシステムか？
2. LLMの品質・コスト・監視について、今困っていることは何か？
3. DatadogなどのSaaSのObservabilityツールは検討したか？断念した理由は？
4. オンプレまたはプライベートクラウドでの構築を検討しているか？
5. もし「LLMの品質管理システムを構築します」という提案が来たら、予算をつけられるか？

**アクション**

- [ ] ヒアリング対象5社をリストアップ（OB・知人・SNS経由でアプローチ）
- [ ] ヒアリング質問票（上記5問ベース）を作成
- [ ] 5社にコンタクトして日程を調整
- [ ] 結果をノーションまたはスプレッドシートにまとめる

### 🏢 E. 初案件獲得（3〜6ヶ月）

**目標**：1社目を3〜6ヶ月以内に受注（目標単価：アセスメント75〜120万円 または 構築300万円以上）

#### 優先アプローチ：官公庁・準公共機関

**理由**
- DS-920施行済みで「規制対応として予算申請しやすい」
- 2026年8月の国産LLM「源内」全府省庁実証開始後、需要が急増する
- cloudpackがSaaS型のため、データ主権が問われる案件で競合が空白になっている

**具体的な営業アクション**

- [ ] **IT調達支援会社・SIer経由のアプローチ**：官公庁への直接営業は難しいため、官公庁向けITサービスを持つ小規模SIer（従業員50〜200名）にパートナー提案
- [ ] **デジタル庁関連のイベント・コミュニティに参加**：Gov-Tech系のイベント、デジタル庁のSlack/Discord等への参加
- [ ] **「DS-920対応無料診断サービス」として入口を下げる**：無料の簡易診断（2時間、Zoomで実施）を提供して顧客接点を作る

#### セカンダリアプローチ：中堅IT企業のCTO

**理由**
- 意思決定が速い（3〜6ヶ月でPoC→本番判断）
- Datadogが高すぎて断念したケースが多く、OSSベースのソリューションに強い関心
- SNS・Qiita・Zennで技術発信後のインバウンドが期待できる

**具体的な営業アクション**

- [ ] LinkedInでCTO・技術責任者に直接アプローチ（週3〜5件のDM）
- [ ] Xで「LLM Observability」タグをフォローし、困っている発言に反応・提案
- [ ] Zenn/Qiitaの記事から問い合わせが来た場合は最優先で対応
