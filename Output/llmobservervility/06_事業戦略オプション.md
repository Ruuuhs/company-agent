# LLM Observability受託事業 戦略オプション

**作成日**: 2026-04-24
**作成者**: 戦略立案者（経営企画部）
**対象読者**: 代表
**ステータス**: ドラフト

---

## エグゼクティブサマリー

LLM Observability受託事業には、現時点で明確な参入機会が存在する。国内専門プレイヤーはcloudpack（KDDIアイレット）がほぼ唯一であり、大手SIerは未参入、グローバルSaaSは日本語・オンプレ対応が不十分という構造的空白がある。推奨は**選択肢A「オンプレ/ハイブリッドLLM Observability専門」**である。金融・製造業大手のデータ主権ニーズは構造的かつ緊急性が高く、大手SIerとの正面衝突を回避しながら高単価案件を獲得できる。先行者優位を確立できる参入ウィンドウは2026〜2027年であり、意思決定と初期実行を6ヶ月以内に行うことが最重要条件となる。最終的な戦略採用の判断は代表にお願いする。

## 1. 現状分析

### 事業環境（外部）

- **市場トレンド**: LLM Observability市場はCAGR 31〜37%で成長中（2024年推定10〜14億ドル → 2029年68億ドル予測）。Gartnerは2028年までにGenAIデプロイの50%でObservability投資が行われると予測（現在15%）。日本国内は2026年がPoC→本番移行の転換期であり、本番運用の安定化ニーズが急拡大する。国内AIシステム市場は2024年1.3兆円から2029年4.2兆円へ（CAGR 25.6%、IDC Japan 2025年）。
- **競合動向**: 大手9社（Datadog、New Relic等）は参入済みだがLLM品質評価の深度は浅い。国内専門プレイヤーはcloudpack（KDDIアイレット）がほぼ唯一でDatadog依存型。大手SIer（NTTデータ、NRI等）はObservability特化サービスを未展開。グローバルスタートアップ（Langfuse、Arize等）は日本語・オンプレ対応が限定的。
- **規制・マクロ環境**: 個人情報保護法・景表法・薬機法・金融商品取引法等の規制産業での法令対応ニーズが顕在化。デジタル庁が国産LLM活用を推進（2026年国産LLM7選選定）。OpenTelemetry GenAI SIGが業界標準として台頭しており、2026年内のStable移行が見込まれる。

### 自社状況（内部）

- **強み**: スタートアップとしての意思決定スピード。大手SIerが手を出さない中堅・スタートアップ向けセグメントへの機動的対応。OSSスタック（Langfuse + ClickHouse + OpenTelemetry + Grafana）を活用したコスト効率の高い構築能力の構築可能性。
- **弱み**: 業界垂直知識・AIコアな知識での差別化が困難。ブランド・顧客基盤・資本力でいずれも大手に劣る。LLMOps×Observability横断人材の採用難が恒常的リスク。
- **現在のリソース・制約**: 新規立ち上げ段階のため人員・実績・資金すべて初期フェーズ。初期投資・採用計画は代表との確認が必要。

## 2. 課題・論点

1. **誰に・何を売るか**: 空白地帯の機会（オンプレ対応、日本語評価、中小企業向け等）のうち、スタートアップとして最も競争優位を発揮できるセグメントはどこか。
2. **いつ参入するか**: 先行者優位のウィンドウが2026〜2027年と判断されるが、技術変化サイクル（6〜12ヶ月）の速さとリソース制約の中でいつ・どこから動くか。
3. **市場成熟後の持続可能性をどう設計するか**: 3〜5年でツール標準機能に組み込まれるリスクへの耐性を、どのポジションで確保するか。

## 3. 戦略オプション

### 選択肢A（推奨）: オンプレ/ハイブリッドLLM Observability専門

#### ポジショニング
データ主権制約を持つ企業（金融・官公庁・大手製造業）向けに、外部SaaS不要のセルフホスト型Observabilityスタックを設計・構築・運用支援する国内唯一の専門プレイヤー。

**誰に**: 金融機関・官公庁・大手製造業（従業員1,000人以上）のCTO・CIO・AI推進部門長
**何を**: Datadog等のクラウドSaaSを使わず、社内環境でLLMの品質・コスト・セキュリティを完全に可視化するObservabilityインフラの構築・運用支援
**どう提供するか**: 初期アセスメント → 設計・構築 → 運用支援・内製化支援の段階的フロー

#### ターゲット顧客セグメント
- 第一優先: 金融機関（メガバンク・地銀・保険）、官公庁・準公共機関
- 第二優先: 大手製造業（自動車・電機・化学）
- 第三優先: 医療・ヘルスケア機関

#### サービスメニュー

| サービス | 内容 | 形式 |
|---------|------|------|
| オンプレObservabilityアセスメント | 現行LLMシステムの可観測性診断、オンプレ対応ツール選定、アーキテクチャ設計 | プロジェクト型 |
| セルフホスト環境構築 | Langfuse OSS + ClickHouse + OpenTelemetry + Grafanaの完全オンプレ/ハイブリッド構築 | プロジェクト型 |
| 業種特化ガードレール実装 | 金融（景表法・金融商品取引法）、医療（禁忌情報）等の法規制準拠チェック実装 | プロジェクト型 |
| LLM品質評価基盤構築 | ハルシネーション検知・日本語文体評価・LLM-as-Judgeの設計・実装 | プロジェクト型 |
| 運用代行・月次レポート | アラート対応、コスト最適化提案、品質推移レポート | 月額継続型 |
| 内製化支援・トレーニング | 顧客エンジニアへのObservability実装スキル移転 | 月額継続型 |

### 選択肢B: 日本語特化LLM品質評価・ガードレール専門

#### ポジショニング
日本語固有の評価課題（敬語・業種固有語彙・法規制対応）に特化し、グローバルSaaSでは解決できない「日本語LLMの品質保証」を受託する専門家として差別化する。

**誰に**: 日本語対応の品質に課題を感じている金融・EC・メディア・ヘルスケア企業
**何を**: 日本語特化の評価ルーブリック設計・LLM-as-Judge実装・ガードレール構築
**どう提供するか**: 評価基準の共同設計 → 自動評価パイプラインの実装 → 継続的品質モニタリング

#### ターゲット顧客セグメント
- 日本語コンテンツを生成AIで量産するEC・メディア（景表法・薬機法対応が必要）
- 金融機関の顧客対応LLMシステム（不適切回答・誤情報ゼロ要件）
- 医療・ヘルスケア（禁忌情報・投薬情報の正確性保証）
- 国産LLM（Takane等）を採用した企業の品質評価基盤

#### サービスメニュー

| サービス | 内容 |
|---------|------|
| 日本語LLM評価基準設計 | 業種・用途別の評価ルーブリック設計（敬語・文体・法規制準拠等） |
| LLM-as-Judge実装 | DeepEval/RAGASの日本語対応版・業種固有ルール組み込み |
| 業種特化ガードレール実装 | NeMo Guardrails/LlamaFirewallを活用した法規制対応フィルタ |
| 評価パイプライン構築 | CI/CDへの品質ゲート組み込み（品質スコア低下時のデプロイ停止） |
| 継続評価・月次レポート | プロンプト変更・モデル更新後の品質変動モニタリング |

## 4. 推奨案と実行計画

**推奨**: 選択肢A（オンプレ/ハイブリッドLLM Observability専門）

**推奨理由**:

1. **空白地帯の競争優位が最も鮮明**: cloudpackはDatadog依存型（SaaS前提）であり、データを外部に出せない金融・官公庁・大手製造業への対応は構造的にできない。この「外部SaaS不可顧客」は需要の深さと急迫度が最も高いセグメントであり、専門プレイヤーとして唯一のポジションを取れる。
2. **高単価×ストック収益の両立が可能**: 構築案件（300万〜800万円）と運用継続（月額50万〜150万円）を組み合わせることで、3年目に累積ストック収益が事業の安定基盤となる。C案（SME向け）は顧客数確保のハードルが高く、B案（品質評価特化）は単価の天井が低い。
3. **参入ウィンドウとの整合性**: 大手SIerの本格参入が1〜2年以内に見込まれるなか、オンプレ専門という技術的参入障壁の高さが先行者優位を守る時間的余裕を生む。CloudSaaS型ツールと競合しないため、Datadog等のグローバルプレイヤーとの衝突も最小化できる。
