# 業界トップレベルになるためのキャッチアップ計画 — LLM Observability 学習地図

**作成日**: 2026-05-02
**情報の有効期限目安**: 2026-11月頃まで有効。以降は主要ツールのアップデートを要再確認
**担当**: トレンドウォッチャー（リサーチ部）
**目的**: 代表が「LLM Observability × Agent領域で業界トップレベルの知見を身につける」ための学習・情報収集の地図を設計する

---

## 0. この計画の使い方

このドキュメントは「何を読むか・何を触るか」のナビゲーションです。読んで終わりではなく、毎週の学習セッションの出発点として繰り返し参照してください。90日後に目指す状態は「業界の中核コミュニティで議論されているトピックについて、自分の言葉で意見を述べられること」です。知識の暗記ではなく、判断力の獲得を目標にします。

## 2. 2025〜2026年の最新トレンドまとめ（Web調査結果）

### 2-1. 主要プレイヤーの最新動向

| プレイヤー | 最新の重要アップデート | 注目度 |
|-----------|---------------------|-------|
| **Langfuse** | 2026年1月にClickHouseが買収（MIT License維持）。月間SDKインストール600万件超。2025年6月にLLM-as-Judge評価・アノテーションキュー・プロンプト実験をMIT化 | 最重要 |
| **Arize Phoenix** | 埋め込み分析・ドリフト検知・eval primitiveで他プラットフォームより統計的リゴア（厳密性）が高い評価を受ける。Velvetを買収 | 高 |
| **LangSmith** | 2025年3月にエンドツーエンドのOpenTelemetryサポートを追加し、ロックインが解消。LangGraph（マルチエージェントフレームワーク）との統合が最も深い | 高 |

| **Promptfoo** | OpenAIが買収。プロンプトのA/Bテスト・LLMレッドチーミング・脆弱性スキャンをYAML設定で実現。CI/CD統合が容易 | 中 |

### 2-2. OpenTelemetry GenAI SIGの最新状況

- **エージェントフレームワーク規約**の策定が進行中。IBM Bee Stack、IBM wxFlow、CrewAI、AutoGen、LangGraphを対象とした共通セマンティック規約のドラフトが策定段階
- **Google AIエージェントホワイトペーパー**を基にした「AIエージェントアプリケーション規約」のドラフトが確立。タスク・アクション・エージェント・チーム・アーティファクト・メモリの属性を定義
- **エージェントスパン向け仕様ページ**が公式ドキュメントに追加（`gen_ai/gen-ai-agent-spans/`）
- **イベント向け仕様**（`gen_ai/gen-ai-events/`）が追加。ストリーミングイベントのトレーシング標準化が進む
- 2026年3月時点で大半がExperimental。2026年内Stable化の見込みは継続

出典: [OTel GenAI Agent Spans 公式](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-agent-spans/)、[OTel AI Agent Observability Blog 2025](https://opentelemetry.io/blog/2025/ai-agent-observability/)

## 3. 必須キャッチアップ領域（3階層）

### L1: 業界全員が知っている前提知識（入場チケット）

これを知らないと「この人は基礎がない」と見なされるレベル。

| トピック | 一言説明 |
|---------|---------|
| トレーシング・スパン・メトリクス・ログの4本柱 | LLMOpsの基礎概念 |
| OpenTelemetryの仕組みとGenAI SIGの存在 | 標準化の現状を知らないと会話に入れない |
| LLM-as-Judge の基本概念と限界 | 評価の話が始まると必ず出る |
| RAGASの4指標（Faithfulness / Answer Relevance / Context Precision / Context Recall） | RAG評価の共通言語 |
| Langfuse・LangSmith・Arize Phoenix の位置付けの違い | どのツールを使っているかで相手の文脈がわかる |
| プロンプトインジェクション・PIIリーク・過剰エージェント権限（OWASP Top 3） | セキュリティ議論の入口 |
| SaaS型 vs セルフホスト型の選択基準 | 日本企業特有の文脈でよく聞かれる |
| トークンコスト管理の基本（モデルルーティング・セマンティックキャッシング） | コスト最適化は経営課題として必ず議題に上がる |

### L2: トップ層が議論している中核トピック（差別化の土台）

業界カンファレンス・専門コミュニティで活発に議論されているレベル。

| トピック | なぜ重要か |
|---------|---------|
| **Eval First 設計**（評価基準を先に設計する方法論） | Hamel Husain / Shreya Shankarが標準化を推進。「デモは動くが本番でダメ」な状況を防ぐ唯一の方法 |
| **OTel GenAI エージェントスパン設計** | マルチエージェントシステムのデバッグはスパン設計の質で決まる |
| **評価データセットの設計と維持** | 良いevalはデータセット構築に始まる。「合成データ生成 vs 本番データの活用」は現在進行中の議論 |
| **LLM-as-Judgeのバイアス対策** | 位置バイアス・自己評価バイアス・格差増幅バイアスの3種が主要問題。対策なしのJudgeは信頼できない |
| **エージェントのデバッグ手法** | リプレイ・巻き戻し・状態スナップショット。AgentOpsが先行。従来のログ分析とは根本的に異なる |
| **CI/CDへのLLM品質ゲート組み込み** | デプロイ前にスコアが閾値を下回ったら自動停止。エンジニアリング規律としての定着 |
| **ドリフト検知と統計的異常検知** | モデルプロバイダーのサイレントアップデートによる品質変動を検知する仕組み |
| **コスト帰属（アトリビューション）** | 「どのユーザー・機能・実験が何円使ったか」を把握しないと意思決定できない |
| **三層コンプライアンスアプローチ** | EU AI Act × NIST AI RMF × ISO 42001の役割分担の理解 |
| **Promptfooによるレッドチーミング** | セキュリティ評価をCI/CDに組み込む最先端の実践 |

### L3: 最先端・未踏領域（差別化チャンス）

現在の研究フロンティア。ここに知見を持つプレイヤーは世界的に少ない。

| トピック | 現状と未踏部分 |
|---------|-------------|
| **エージェント評価のベンチマーク設計** | エンドツーエンドの成功率では内部の意思決定プロセスが見えない。「アーキテクチャ考慮型評価指標」の研究が始まったばかり（arXiv 2025）|
| **マルチモーダルObservability** | 画像・音声・動画を含むLLMシステムの品質監視は実用的な手法がほぼ未整備 |
| **自動根本原因分析（Auto-RCA）** | 問題の検知から「なぜ失敗したか」の自動診断まで自動化する研究が始まっている。現状は人手が必須 |
| **エージェントの意思決定可視化（XAI + Obs）** | Gartnerが2028年の差別化要素と予測。「なぜエージェントがこの判断をしたか」の説明可能性 |
| **フィードバックループの自動化** | 本番ログ → 評価 → データセット生成 → ファインチューニング → デプロイのサイクルを完全自動化する研究 |
| **セマンティックテレメトリ** | ログをLLM自身が自然言語で解釈してself-diagnosisを行う新概念（2026年に概念が登場したばかり） |
| **評価のキャリブレーション科学** | LLM-as-Judgeのスコアが人間評価とどれだけ一致しているかを継続的に検証・改善する方法論の標準化 |
| **日本語特化Observability手法** | 敬語一貫性・曖昧表現・法規制準拠の自動評価は世界的に未整備。国内での独自研究が差別化の核になりうる |

## 5. 90日キャッチアップロードマップ（週次粒度）

### 基本方針

- **Week 1〜4（Month 1）**: L1の完全制覇 + L2の入口。「何が存在するか」を地図として把握する
- **Week 5〜8（Month 2）**: L2の深掘り + ハンズオン。「実際に手を動かす」ことで概念が定着する
- **Week 9〜13（Month 3）**: L2〜L3の橋渡し + アウトプット。「自分の言葉で説明できる状態」を作る
