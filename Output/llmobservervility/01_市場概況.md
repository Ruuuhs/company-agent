## エグゼクティブサマリー

LLM Observability市場は2024年時点で推定10〜14億ドル規模（調査機関により差異あり）であり、CAGR 31〜37%という極めて高い成長率で拡大している。2029年には最大68億ドル、2034年には80〜170億ドル超に達すると複数機関が予測する。成長の主要ドライバーは、エンタープライズにおける生成AI本番運用の拡大、ハルシネーション・コスト制御・コンプライアンスへの組織的対応の急務化である。LLMの非決定論的挙動という本質的な特性が、従来のAPMツールでは対応不能なモニタリングの空白を生んでおり、専用プラットフォーム市場が急拡大している。この市場は参入余地が大きく、特に金融・ヘルスケア・エンタープライズ向けの高信頼性・コンプライアンス対応ソリューションに強い需要が存在する。

## 1. LLM Observabilityとは何か

### 【事実】定義

**LLM Observability**とは、LLMモデルまたはLLMを使用したアプリケーションから、その行動・パフォーマンス・出力特性に関するデータをリアルタイムで収集・分析・可視化するプロセスである。

IBM（2024）による定義：

> 「LLMアプリケーション、API、ワークフローから関連するメトリクス・トレース・ログを収集し、開発者がアプリケーションを効率的・予防的・スケーラブルに監視・デバッグ・最適化できるようにする。」

具体的には以下の4種類のシグナルを同時に監視する。

| シグナル種別 | 監視対象の例 |
|-----------|------------|
| トレース | プロンプト→モデル呼び出し→レスポンスの処理フロー |
| メトリクス | レイテンシ・トークン使用量・コスト・エラー率 |
| ログ | 入出力ペア・ツール呼び出し結果・エージェント推論ステップ |
| 評価（LLM固有） | ハルシネーション率・関連性スコア・セマンティックドリフト |

### 【事実】従来のAPMとの根本的な違い

| 比較軸 | 従来のAPM | LLM Observability |
|-------|----------|-----------------|
| 監視対象 | レイテンシ・スループット・エラーコード | + 出力の「正しさ」・意味的品質 |
| システムの性質 | 決定論的（同一入力→同一出力） | 非決定論的（確率的出力） |
| 成功判定 | HTTPステータス200・レイテンシ閾値 | 応答が正確・安全・文脈適切かどうか |
| 障害検知 | タイムアウト・例外・ダウン検知 | ハルシネーション・プロンプトドリフト・ツール誤選択 |
| コスト管理 | サーバーコスト中心 | + APIトークン消費量・モデル別コスト |

LangChain（2025）による指摘：

> 「レスポンスは高速で、ブランドトーンに合っていて、それでも間違っている可能性がある—ハルシネーション、安全でない内容、または誤った文脈に忠実である場合がある。これが、LLM Observabilityが評価機能をインフラダッシュボードと組み合わせる理由だ。」

Datadog公式ドキュメント（2025）による指摘：

> 「従来のAPMは検索に400ms、LLM呼び出しに1.2秒かかったことを示せる。しかし示せないのは、検索が誤った製品の文書を返したこと、LLMがコンテキストにない詳細をハルシネーションしたこと、エンジニアが無関係なコードを修正したときにシステムプロンプトがドリフトしたことだ。」

### 【考察・示唆】

LLMの「成功した呼び出しでも誤った回答を返す」という特性は、従来の監視ツールベンダーが既存製品の機能追加だけでは対応しにくい構造的ギャップを生んでいる。これはスタートアップ専用ツールと大手ベンダーの追加モジュールが並走する市場構造を生み出しており、差別化ポイントは「評価（Evals）の品質」と「コスト管理の精度」に集約されていく可能性が高い。

## 5. バリューチェーン

### 【事実】LLM Observabilityのバリューチェーン全体像

LLM Observabilityは4つのレイヤーで構成される。各レイヤーに異なるプレイヤーが参入し、独自の価値を提供している。

```
[ データ収集 ] → [ 分析パイプライン ] → [ 可視化・アラート ] → [ アクション・最適化 ]
```

#### レイヤー1: データ収集（インストゥルメンテーション）

| 収集対象 | 具体的なシグナル | 標準/技術 |
|---------|--------------|---------|
| LLM入出力 | プロンプト・レスポンスペア、システムプロンプト | OpenTelemetry GenAI Semantic Conventions |
| トークン使用量 | `gen_ai.usage.prompt_tokens` / `gen_ai.usage.completion_tokens` | OpenLLMetry（Traceloop） |
| レイテンシ | 初回トークン時間（TTFT）・総生成時間 | OpenTelemetry |
| ツール呼び出し | エージェントが選択したツール・引数・結果 | LangChain / LangGraph トレース |
| RAGパイプライン | ベクター検索・文書関連性スコア・引用精度 | Langfuse / Arize Phoenix |
| インフラ | GPU使用率（NVIDIA DCGM）・メモリ・スループット | Datadog / Dynatrace / New Relic |

**主要標準**: OpenTelemetry（OTel）のGenAI Semantic Conventionsが業界標準として台頭。Traceloopの**OpenLLMetry**はOTelの拡張として設計され、そのセマンティック規約はOTel本体に取り込まれた。Datadogも2025年にOTel GenAI Semantic Conventionsのネイティブサポートを発表。

#### レイヤー2: 分析パイプライン（評価・異常検知）

| 分析機能 | 内容 |
|---------|------|
| ハルシネーション検知 | LLM出力がRAGコンテキストの情報と乖離している場合を自動検出 |
| セマンティックドリフト検知 | プロンプト・レスポンスの意味的変化を継続監視 |
| LLM-as-a-Judge評価 | 別のLLMが応答の正確性・関連性・一貫性を評価 |
| コスト分析 | トークン→API費用換算・ユーザー別・機能別コスト配賦 |
| 自動プロンプト最適化 | Few-shot Bayesian・MetaPrompt等のアルゴリズムによる最適化 |

#### レイヤー3: 可視化・アラート

| 機能 | 内容 |
|-----|------|
| Observabilityダッシュボード | モデル別・スパン別・アプリ環境別のパフォーマンス表示 |
| アラートルール | ハルシネーション率閾値・コスト超過・エラー率上昇 |
| トレースビュー | エンドツーエンドの推論フロー（RAG→LLM→ツール→レスポンス）可視化 |

#### レイヤー4: アクション・最適化

| アクション | 内容 |
|----------|------|
| プロンプトエンジニアリング改善 | 評価メトリクスに基づくプロンプト修正・AB比較 |
| コスト最適化 | 未使用コンテキスト削除・冗長APIコール排除・モデルダウングレード判断 |
| セキュリティ・ガードレール | プロンプトインジェクション検知・PII漏洩防止 |
| 規制対応 | 監査ログ生成・説明可能性レポート・コンプライアンスダッシュボード |

### 【考察・示唆】

OpenTelemetryが業界標準として確立しつつあることは、ベンダーロックインリスクを低下させ、企業の導入障壁を下げる効果がある。同時に、差別化が難しくなるため、各ベンダーは「評価アルゴリズムの精度」「ドメイン固有の組み込みルール」「UXの使いやすさ」で競争することになる。

## 8. データ品質の注記

- **市場規模データの幅**: 調査機関によって2024年市場規模に5億〜14億ドルの幅がある。これは「LLM Observability Platform」の定義範囲（専用ツールのみか、AI Observability全体を含むか）の違いによる。特定の数字を経営判断の根拠にする場合は、該当レポートの定義を必ず確認すること。
- **データの鮮度**: 本レポートで引用したデータは2024年〜2025年発行のものを中心としている。ただし市場成長速度が極めて高いため、半年〜1年で状況が大きく変わる可能性がある。
- **調査会社の信頼度**: 本レポートで引用したMordor Intelligence・Market.us・Custom Market Insights等の調査会社レポートは有料の二次情報であり、一次データ（政府統計・上場企業IR等）ではない。政府・公的機関による公式統計は現時点でこの新興市場には存在しないため、調査会社データを「参考情報」として扱い、過信しないこと。
- **企業事例のバイアス**: ベンダー公式サイトや比較記事を出典とする事例は、一定のポジティブバイアスが存在する可能性がある。
- **EU AI Act施行スケジュール**: 2025年11月時点でEU委員会が高リスク義務を2027年12月まで16ヶ月延期する提案を行っているが、欧州議会・理事会の承認待ちの状況であり、今後変更の可能性がある。
