## Tier 1：LLM Observability構築（入口・差別化の核）

### ポジション
**「ISMAP準拠のLLM Observabilityを設計・構築できる国内唯一の専門家」**

### なぜここが参入の入口か

**ISMAPという「ロック」がある：**

| LLM Observabilityツール | ISMAP認証 | 官公庁・金融で使えるか |
|------------------------|---------|------------------|
| Datadog LLM Obs | **なし（SaaS、外部送信あり）** | ❌ |
| Langfuse（SaaS版） | **なし** | ❌ |
| Arize / LangSmith 等 | **なし** | ❌ |
| **Langfuse OSS（セルフホスト）** | **ISMAP登録クラウド上に構築可** | ✅ |

→ 「ISMAP対応のLLM Observability」というカテゴリに、**現在競合が存在しない**

### 具体的な構成（提供できる唯一のアーキテクチャ）

```
【官公庁・金融機関が使える構成】

Azure（ISMAP登録・東日本リージョン）
  または AWS（ISMAP登録・ap-northeast-1）
    ↓ 外部にデータが出ない
  Langfuse OSS（セルフホスト）
  ClickHouse（高速ログDB・セルフホスト）
  OpenTelemetry Collector（標準化されたトレース収集）
  Grafana（ダッシュボード・セルフホスト）
    ↓
  【実現できること】
  ・プロンプト/レスポンスのISMAP準拠ログ保管
  ・ハルシネーション自動検知
  ・コスト・レイテンシのリアルタイム可視化
  ・DS-920・FISC第13版の要件証跡自動生成
```

|---------|------|------|
| 現状アセスメント + 要件整理 | 75〜120万円 | 3週間 |
| ISMAP準拠Obs環境構築（標準） | 250〜500万円 | 4〜8週間 |

## Tier 2：LLM品質評価サービス（Evals as a Service）

### ポジション
**「LLMが正しく動いているかを継続的に数値で証明する」評価専門サービス**

### なぜTier 1の次に来るか

Observabilityは「見る」だけ。Evalsは「正しいか判定する」。
Tier 1構築後の顧客に「次は品質を定期評価しましょう」と自然につながる。

### 具体的なサービス内容

**月次品質レポート（継続型）**

| 評価指標 | 内容 | 対応ツール |
|---------|------|----------|
| Faithfulness（忠実性） | 回答がソース文書と整合しているか | RAGAS |
| Answer Relevance（適切性） | 質問と回答が関連しているか | RAGAS / DeepEval |
| ハルシネーション率 | 嘘・誤情報の発生頻度 | LLM-as-Judge |
| **日本語文体評価** | 敬語・専門用語・文体の適切さ | **独自実装（差別化）** |
| **有害表現検出（日本語）** | 差別・不適切表現の日本語検出 | **独自実装（差別化）** |

**プロンプト改善コンサルティング（プロジェクト型）**

評価データを基に「どのプロンプトを変えると品質が何%改善するか」を提案。
実装後の効果検証まで一気通貫で支援。

### 価格・収益

| サービス | 価格 |
|---------|------|
| 月次品質評価レポート（LLM-as-Judge + RAGAS） | 月額60〜120万円 |
| プロンプト改善プロジェクト | 150〜300万円/プロジェクト |
| 日本語評価基準のカスタム設計 | 200〜400万円/プロジェクト |

### 差別化ポイント：日本語評価の空白

グローバルの評価ツール（RAGAS, DeepEval, Braintrust等）は英語前提で設計されており、日本語の品質評価に弱い。
→ 「日本語LLMの品質を、日本語の文脈で正しく評価できる」という軸は、グローバルSaaSが埋められない差別化になる。

## Tier 3：AIエージェント観測・最適化（Agent AX）

### ポジション
**「複雑なAIエージェントを診断して、なぜ失敗するかを特定し、改善する」専門サービス**

### 「AX」（エージェント体験）とは何か

AIエージェントが普及するにつれて、「エンドユーザーがエージェントと対話する体験品質」が問われるようになる。これを「Agent Experience (AX)」と呼ぶ。

具体的には：
- エージェントが正しいツールを選択しているか
- エージェントの回答が一貫しているか（同じ質問に毎回同じ品質で答えるか）
- 複数のサブエージェントが協調して動いているか（マルチエージェント）
- エージェントが「暴走」しないか（コスト・時間の上限管理）

### 市場の現状

| 数字 | 意味 |
|------|------|
| エージェント採用組織：9% → 18%（1年で倍増） | 需要が爆発的に増えている |
| エージェント本番運用の94%が何らかのObservabilityを実装 | 「必要」と理解されている |
| 1リクエストが10〜20回のLLM呼び出しに展開 | 従来のAPMでは追跡不可 |
| レート制限超過がエラーの60%を占める | 監視なしでは原因不明のエラーが続く |

### 具体的なサービス内容

**エージェント診断・構造可視化（入口）**

```
[What We Do]
顧客のAIエージェントに対して：
  1. スパンごとのトレース取得（LangGraph/CrewAI/AutoGen対応）
  2. ボトルネックとなっているステップの特定
  3. 「なぜ失敗したか」の根本原因分析
  4. コスト最適化の余地特定（どのステップを削減できるか）
  5. 改善後の効果測定

[成果物]
エージェント診断レポート（20〜30ページ）
+ 改善優先度マトリクス
+ 修正後の効果予測
```

**エージェント設計コンサルティング（高単価）**

「どのようにエージェントを設計すれば壊れにくいか」を設計段階から支援。
- ツール選択の設計レビュー
- エラーハンドリング・リトライ設計
- コスト上限・タイムアウト設計
- テスト・評価フレームワークの設計

### 価格・収益

| サービス | 価格 |
|---------|------|
| エージェント診断・可視化 | 150〜300万円/件 |
| エージェント設計コンサル + 実装支援 | 300〜800万円/件 |
| エージェント品質監視（継続） | 月額100〜250万円 |

## 戦略の強み：フライホイール効果

```
[フライホイールの構造]

Observabilityで「データ」が蓄積される
        ↓
蓄積されたデータがEvalsの「精度」を高める
        ↓
高精度なEvalsが「改善提案」の根拠になる
        ↓
改善によりエージェントの「品質」が上がる
        ↓
品質が上がると顧客の「依存度・継続率」が高まる
        ↓
長期的にデータが蓄積され、他社が真似できない「日本語LLM品質のベンチマーク」が生まれる
```

→ データが資産化していく構造。競合が後から参入しても追いつけない。

## 優先順位と推奨ロードマップ

### Phase 0〜1（2026年〜）：Tier 1に集中

**理由**：
- ISMAP×オンプレの空白地帯は今すぐ参入できる
- Evalsも大事だが、まずObsで実績を作ることが先
- Agent AXは市場がまだ黎明期。技術のキャッチアップを続けながら、Tier 1顧客にエージェントが広がった段階で提供開始

**Tier 1でやること**：
- 官公庁 × DS-920対応案件：3ヶ月以内に1件
- ISMAP準拠Langfuse構成のリファレンスアーキテクチャをGitHubで公開

### Phase 2（2027年〜）：Tier 2を確立

**理由**：
- Tier 1の構築案件が増えると「その後の品質管理どうするか」という相談が自然に来る
- Tier 2は月次継続なのでARRが安定する（解約率が低い）
- 日本語評価の差別化を早期に確立しておく

**Tier 2でやること**：
- 月次品質レポートのテンプレート化
- RAGAS + 日本語カスタム評価の組み合わせを型化
- 最初の月次顧客を3社獲得

### Phase 3（2027年後半〜）：Tier 3への拡張

**理由**：
- AIエージェント市場は2026年から爆発的に拡大している
- Tier 1/2の実績でObservabilityの専門家として認知が確立した後に参入が自然
- Agent AXは「エージェント設計」への関与なので、SI的な高単価が取れる

## リスク分析と対策

| リスク | 深刻度 | 対策 |
|--------|--------|------|
| 小規模チームで3サービスは広すぎる | 高 | Phase分けして順番に展開。Tier 1が安定するまでTier 2/3は「準備」のみ |
| 「Agent AX」の定義が曖昧 | 中 | 初期は「エージェント診断レポート」という具体的な成果物で提供 |
| ISMAP対応の技術習得コスト | 中 | 最初の1案件でIAMSP対応Langfuse構成を構築し、そのまま実績化 |
| 日本語評価のツール開発コスト | 中 | 最初はLLM-as-Judgeの日本語プロンプトで代替。徐々に型化 |
| 大手SIerが真似してくる | 低（1〜2年の猶予） | Tier 1で実績・ブランドを確立。データ資産でロックイン |
