# 官公庁・政府機関におけるAI/LLM利用基準・ガイドライン調査レポート
## 受託事業（LLM Observability構築支援）への示唆

**作成日**: 2026-04-24
**情報の有効期限目安**: 2026-10頃まで有効。以降は要再確認（各ガイドラインが随時改訂中のため）
**担当**: トレンドウォッチャー（リサーチ部）
**調査対象**: 官公庁・政府機関のAI/LLM利用基準と、受託事業者として知るべき規制・要件

---

## エグゼクティブサマリー

官公庁のLLM利用は「試験導入フェーズ」から「本格展開フェーズ」へ移行しつつある。デジタル庁が2026年3月に国産LLM7モデルを選定し、全府省庁18万人規模での実証が2026年8月より開始予定。同時に、監視・ログ・監査に関する要件が具体化されてきており、LLM Observabilityは「あると便利」から「政府調達の必須条件」になりつつある。

受託事業者として押さえるべき要点は3つ。
1. デジタル庁DS-920ガイドライン（2025年5月策定）が政府調達の事実上の標準となっており、調達チェックシートへの対応が受注の前提条件になる
2. 個人情報保護委員会・NISCの要件から、プロンプト記録・出力ログ・アクセス制御の三点セットが最低限必要
3. ISO/IEC 42001（JIS Q 42001:2025として発行済み）への対応が、競合他社との差別化ポイントになる

## 1. デジタル庁

### 1-1. 生成AI調達・利活用ガイドライン（DS-920）

**正式名称**: デジタル社会推進標準ガイドラインDS-920「行政の進化と革新のための生成AIの調達・利活用に係るガイドライン」
**発行日**: 2025年5月27日
**管轄**: デジタル庁
**位置づけ**: 政府情報システム調達における生成AI利用の最上位基準

**主な内容（事実）**

対象を「LLMを構成要素とするテキスト生成AI」に限定し、以下の構造で政府AIガバナンスを整理している。

| 項目 | 内容 |
|------|------|
| ガバナンス体制 | 各府省庁にCAIO（Chief AI Officer）を設置し、利活用の把握・推進・リスク管理を総括 |

| 人間によるチェック | Human-in-the-Loopを絶対条件とし、AI出力への依存を制限 |
| 技術的リスク | データ汚染攻撃・学習データの偏り・ハルシネーション・説明責任の不足を明記 |
| 先進的AI利活用アドバイザリーボード | 2026年1月第2回開催。ガイドライン充実に向けた改定方針を継続的に審議 |

## 2. 総務省・経済産業省

### 2-1. AI事業者ガイドライン

**正式名称**: AI事業者ガイドライン（第1.1版）
**発行日**: 第1.0版 2024年4月19日 / 第1.01版 2024年11月22日 / 第1.1版 2025年3月28日
**管轄**: 総務省・経済産業省（共同策定）

**位置づけ（事実）**

AIの開発者・提供者・利用者など複数の立場の事業者を対象とした、国内AI利用に関する統一的ガバナンス指針。複数省庁が個別に発行していたガイドラインを統合したもの。「Living Document（生きた文書）」として継続的に改訂される設計。

**基本原則（事実）**

7原則を掲げる。
1. 人間中心のアプローチ
2. 安全性
3. 公平性
4. プライバシー保護
5. セキュリティの確保
6. 透明性
7. 説明責任

**透明性要件（事実）**

透明性は以下の方法で実現するとされている。
- ログ記録（Logging Records）の保存と開示
- モデルの能力と限界の開示による検証可能性の向上
- 先進的AIシステムの能力・限界・適切/不適切な利用領域の開示

第1.1版ではEU AI Act（2024年8月施行）対応の記載と、先進的AIシステムの「国際行動規範」に対応した自己評価・報告方法（2025年2月開始）が追加された。

- 経産省公式（第1.1版概要）: https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/pdf/20250328_2.pdf
- 総務省公式（第1.1版本文）: https://www.soumu.go.jp/main_content/001002576.pdf

## 3. NISC（内閣サイバーセキュリティセンター）

### 3-1. 政府機関等の統一基準群（令和5年度版）とAI関連要件

**正式名称**: 政府機関等のサイバーセキュリティ対策のための統一基準群（令和5年度版）
**発行日**: 2023年7月（令和5年度版）
**管轄**: NISC（内閣サイバーセキュリティセンター）

**主な内容（事実）**

政府機関の情報セキュリティポリシー策定の標準を定める文書群。AI/LLMに直接言及した専用章は令和5年度版時点では設けられていないが、以下の形でAI利用に関係する。

- **クラウドサービス利用要件**: 政府機関がクラウドサービスを利用する場合、原則としてISMAPクラウドサービスリストに掲載されたサービスから調達（= LLMサービス自体のISMAP登録が求められる）
- **サプライチェーンリスク**: 委託先・外部サービス利用時のリスク管理が明記されており、LLMベンダーへの委託もサプライチェーン管理の対象となる
- **ログ・監査**: 情報システムのログ取得・保存・監査を義務化。LLM利用システムにもこの要件が適用される

**2025年の動向（事実）**

2025年2月、NISCは政府機関向けに生成AIサービスの業務利用に関する注意喚起を発出。クラウドサービスへのAI機能追加についても監視を強化している。

**ISMAP-LIUとAI（事実）**

生成AIサービスのGaiXer（Azure OpenAI Service基盤、株式会社FIXER提供）が2024年12月にISMAP-LIU（低リスク利用向け）の特別措置サービスリストに登録。政府機関が安全な生成AI環境を調達する際の参照リストとなっている。

**出典**:
- NISC統一基準改定案（令和5年度）: https://www.nisc.go.jp/pdf/policy/general/gaiyor5.pdf
- サイバーセキュリティ2025: https://www.nisc.go.jp/pdf/policy/kihon-s/cs2025.pdf
- NRI Secure解説: https://www.nri-secure.co.jp/blog/unified-standard-group-r5

## 4. 個人情報保護委員会

### 4-1. 生成AIと個人情報に関する注意喚起・ガイダンス

**主要文書**: 「生成AIサービスの利用に関する注意喚起等」
**発行日**: 2023年6月2日
**管轄**: 個人情報保護委員会

**主な内容（事実）**

個人情報取扱事業者が本人の同意なく生成AIサービスに個人データを含むプロンプトを入力し、その個人データが応答出力以外の目的（学習データ等）で利用される場合、個人情報保護法違反となる可能性を明示。

具体的な注意事項として以下を列挙している。
- プロンプトに個人情報を入力した場合、学習データとして収集される可能性がある
- 要配慮個人情報（人種・信条・病歴・前科等）の無断入力は特に問題となる
- サービス事業者の利用規約（特にデータの学習利用に関する条項）の確認を義務化

**2025〜2026年の制度改正動向（事実）**

2026年1月9日公表の制度改正方針では12項目の改正方針が明確化されており、以下が含まれる。
- 課徴金制度の導入
- 同意規制の見直し（生成AI等の公益利用における例外規定の検討）
- 委託先規律の強化

**出典**: 個人情報保護委員会公式: https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert/

### 4-2. OpenAIへの行政指導（2023年6月）

**発行日**: 2023年6月2日

**内容（事実）**

個人情報保護委員会はOpenAI（ChatGPT提供企業）に対し、行政指導を実施。本人の同意なしにChatGPT利用者および利用者以外の要配慮個人情報（人種・信条・社会的身分・前科・前歴・病歴等）を取得しないよう要請。

これは海外AI事業者への日本初の実質的な行政指導として記録されており、以降のLLM利用に関するコンプライアンス論議の出発点となっている。

## 5. ISO/IEC関連規格

### 5-1. ISO/IEC 42001（AI管理システム）

**規格番号**: ISO/IEC 42001:2023
**発行日**: 2023年12月18日（国際規格）/ 2025年8月20日（JIS Q 42001:2025として日本国内発行）
**JIS対応**: JIS Q 42001:2025「情報技術－人工知能－マネジメントシステム」として正式発行済み

**概要（事実）**

AIに関する初のマネジメントシステム国際規格。AIシステムを開発・提供・使用する組織を対象に、リスクベースアプローチによるAIマネジメントシステムを規定。信頼性・透明性・説明責任を備えたAI運用の枠組みを提供する。

日本からは多数の専門家が参加し、規格策定に積極的に貢献した経緯がある。

**日本国内での採用状況（事実）**

- 2025年4月3日: SGSジャパンが株式会社Godotに対し、SGSグループとして日本初のISO/IEC 42001認証を発行
- ISMS認定センター（ISMS-AC）は2025年2月にAIMS認定開始を決定
- 邦訳版（JSA発行）は2024年4月15日発行済み

**出典**:
- ISMS-AC: https://isms.jp/topics/news/20250820-1.html
- 経産省プレスリリース: https://www.meti.go.jp/press/2023/01/20240115001/20240115001.html

### 5-2. ISO 27001（ISMS）とAI/LLMの関係

**現状（事実）**

ISO 27001はISMAP管理基準の主要参照元であり、政府クラウド調達の基盤となっている。LLMサービスへの適用においては、以下が求められる。

- アクセス制御（LLMへのアクセスログ記録）
- データ分類（プロンプト入力データの機密度分類）
- インシデント管理（LLM出力による情報漏洩インシデントの管理手順）
- サプライヤー関係（LLMベンダーとの契約・評価管理）

ISMAP管理基準は現在見直し中（2024年12月発表）であり、ISO 27000シリーズの改訂を反映して管理策数を数百まで削減するリスクベースアプローチへの移行が予定されている。

**出典**: https://jtrustc.co.jp/knowledge/ismap_2504/

## 7. 受託事業（LLM Observability構築支援）への具体的示唆

### 7-1. LLM Observabilityで監視・記録すべき項目（基準対応マッピング）

以下は各基準・ガイドラインから導出した、最低限実装すべき監視・記録項目の一覧。

| 監視・記録項目 | 根拠となる基準 | 優先度 |
|------------|-------------|------|
| 全プロンプト入力の記録（タイムスタンプ・ユーザーID付き） | DS-920・NISC統一基準・ISO 27001 | 最優先 |
| 全AI出力の記録（プロンプトとの紐付き） | DS-920・AI事業者ガイドライン（透明性要件） | 最優先 |
| 個人情報・要配慮個人情報の入力検知・アラート | 個人情報保護法・PPC注意喚起 | 最優先 |
| プロンプトインジェクション検知・ブロックログ | デジタル庁リスク対策ガイドブック | 高 |
| ハルシネーション検出・フラグ付与 | DS-920・AI事業者ガイドライン | 高 |
| アクセス制御ログ（誰がいつLLMにアクセスしたか） | ISMAP・NISC統一基準・ISO 27001 | 高 |
| 有害出力の検知・フィルタリングログ | DS-920調達チェックシート「有害情報の出力制御」 | 高 |
| 外部LLMベンダーへのデータ送信記録 | 個人情報保護法（第三者提供）・NISC サプライチェーン要件 | 高 |
| 利用量・コスト・レイテンシのメトリクス | ISO/IEC 42001（AIマネジメントシステム） | 中 |
| Human-in-the-Loop確認の記録 | DS-920（人間による最終確認が絶対条件） | 中 |

### 7-2. 受託事業者として提供すべきコンプライアンス支援メニュー

**A. 導入前アセスメント（即時提案可能）**

「どの基準に準拠する必要があるか」を整理するアセスメントサービス。官公庁か民間企業か・扱うデータの機密度・既存クラウド環境（ISMAP登録済みか）の3軸で準拠すべき基準を特定し、Observabilityの設計要件を定義する。

**B. ログ設計・実装支援（核心サービス）**

DS-920・NISC統一基準・個人情報保護法の各要件に対応したログ項目の設計から実装までを支援。特に以下の差別化要素を前面に出す。
- 個人情報検知（PII Detection）機能の組み込み
- プロンプトインジェクション検知ルールの設計
- 監査ログの改ざん防止設計（ログの完全性保証）

**C. ISO/IEC 42001・ISMAP対応支援（高単価）**

ISO/IEC 42001の認証取得を目指すお客様向けに、AIマネジメントシステムの構築とObservabilityの統合を一体提供。JIS Q 42001:2025（2025年8月発行）に準拠した文書化支援も含める。

**D. ダッシュボード・レポーティング支援（継続収益）**

CAIO（各府省庁のChief AI Officer）向けのAI利用状況ダッシュボードの構築。月次レポートの自動生成とアラート設定。

### 7-3. 基準対応が受注の決め手になる場面の想定

**場面1: 政府・自治体への直接受注**

DS-920ガイドラインの調達チェックシートへの対応が選定要件に含まれる。「有害情報の出力制御」「ログ保存」「ハルシネーション対策」の各項目で具体的な実装実績を示せる事業者が優位に立つ。

2026年8月から全府省庁で源内の大規模実証が始まるため、2026年度下半期〜2027年度にかけて自治体・府省庁からの整備案件が急増すると予測する。

**場面2: 官公庁を顧客に持つSIerへのBtoB提案**

SIerが官公庁向けシステムにLLMを組み込む際、Observabilityの実装をサブコンとして担う構造。この場合、SIerが準拠すべき基準（ISMAP・DS-920等）を先回りして理解し、提案書に「この基準のXX要件に対応済み」と明記することが差別化になる。

**場面3: 民間企業のAI事業者ガイドライン対応支援**

AI事業者ガイドライン（第1.1版）の透明性要件「ログ記録の保存と開示」への対応を求められる事業者向け。第三者認証（ISO/IEC 42001）の取得を目指す企業には、Observabilityを「認証対応の証跡管理システム」として位置づけて提案できる。
