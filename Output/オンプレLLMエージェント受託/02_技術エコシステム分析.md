## エグゼクティブサマリー

オンプレLLMエージェント市場は、データ主権・セキュリティ要件の高い金融・医療・製造業を中心に急速に立ち上がっている。オンプレLLM提供プラットフォームの世界市場は2025年の30.8億ドルから2026年には38.1億ドルへ成長し、CAGR 23.8%で拡大中（出典: GII調査、2025年）。

技術スタックは「基盤モデル→推論エンジン→エージェントフレームワーク→RAG/ベクターDB→監視」という5層構造が標準化しており、各層にOSSが整備されている。受託スタートアップとして習得すべき最優先スキルは、**vLLM/SGLangによる推論サーバー構築**・**LangChain/LangGraphによるエージェント実装**・**日本語LLMのファインチューニング**の3点である。

## A. コア技術の概要

### オンプレLLMエージェントとは（平易な説明）

「オンプレLLMエージェント」とは、ChatGPTのような外部のAIサービスを使わず、自社のサーバーや社内ネットワークの中だけで動かすAIのことです。このAIは単に質問に答えるだけでなく、「ツールを自分で選んで使う」「複数の処理を順番に実行する」「判断してメールを送るなど行動まで行う」という「エージェント（代理人）」としての機能を持ちます。

企業にとって最大の価値は「データが外に出ない」点にあります。病院の患者情報、銀行の取引データ、工場の生産データを、外部クラウドに送ることなくAIで処理できます。

### 技術的な定義

- **オンプレLLM**: オープンウェイト（重みが公開された）モデルを自社GPU上でホストし、OpenAI互換のAPIとして提供する仕組み
- **エージェント機能**: ツール呼び出し（Function Calling）、ReAct（思考→行動→観察のループ）、マルチエージェント協調による自律的なタスク実行
- **主な構成**: 推論エンジン（vLLM等）+ エージェントフレームワーク（LangChain等）+ RAG（ベクターDB + 埋め込みモデル）

### なぜ今オンプレ需要が高まっているのか

| 要因 | 内容 |
|------|------|
| データ主権・法規制 | 個人情報保護法・GDPR・業界規制（FISC・HIPAA等）でデータの外部送信が制限される業界が増加 |
| コスト優位 | オンプレ運用はクラウドAPIに比べ最大18倍のトークンコスト削減が可能（Accrets調査、2025年）|
| モデル品質の向上 | 7B〜70BのオープンウェイトモデルがGPT-4o水準に接近。クラウドAPIとの品質差が縮小 |
| 日本語特化モデル登場 | Swallow・LLM-jp・ELYZAなど日本語に最適化されたOSSモデルが充実 |
| GPU調達のしやすさ | RTX 4090（7B〜13Bモデル対応）が民生品として入手可能。中小企業でも導入可能な価格帯 |

出典: [Accrets - On-Premise LLM Deployment](https://www.accrets.com/general/on-premise-llm-deployment/)（2025年）、[allganize.ai](https://www.allganize.ai/en/blog/enterprise-guide-choosing-between-on-premise-and-cloud-llm-and-agentic-ai-deployment-models)（2025年）

### クラウドLLM vs オンプレLLM — トレードオフ比較

| 比較軸 | クラウドLLM（OpenAI等） | オンプレLLM |
|--------|----------------------|------------|
| **データプライバシー** | データが外部サーバーに送信される | データが社内で完結。法的リスクが低い |
| **モデル品質（最高水準）** | GPT-4o/Claude 3.5 Sonnet等、最高水準 | クラウド最高水準には一歩劣るが差は縮小中 |
| **コスト構造** | 従量課金（使うほど高額） | 初期CAPEX大（200万〜1,500万円）、月次OPEX小 |
| **カスタマイズ性** | プロンプトのみ | ファインチューニング・継続事前学習まで可能 |
| **レイテンシ** | ネットワーク依存 | 社内完結で低レイテンシ |
| **スケーラビリティ** | 即時スケール可能 | GPU増設が必要（リードタイム5〜6ヶ月） |
| **メンテナンス負担** | プロバイダー任せ | 自社でのモデル更新・インフラ管理が必要 |
| **オフライン運用** | 不可 | 可能（工場・医療機関等） |

**結論**: 2025年時点の最適解は「ハイブリッド」。機密データ処理はオンプレ、高度な推論はクラウドAPIという使い分けが大企業で主流化している。

### 技術の進化の方向性

| 時期 | 主なトレンド |
|------|------------|
| **現在（2025〜2026年）** | エージェントが「Peak of Inflated Expectations」（Gartner 2025）。7B〜70Bモデルが実用水準に到達。マルチエージェント・RAGが標準構成に |
| **1年後（2026〜2027年）** | 推論コストがさらに90%以上低下見通し（Gartner予測、2026年3月）。マルチモーダル（画像・音声）がオンプレでも実用化。エッジ/NPU展開が拡大 |
| **3年後（2028年〜）** | 企業アプリの33%以上が自律型エージェントを内包（Gartner予測）。ドメイン特化型SLM（Small Language Model）がオンプレ主流に。専用NPUチップが普及しGPU依存が低下 |

出典: [Gartner Hype Cycle for AI 2025](https://www.gartner.com/en/newsroom/press-releases/2025-08-05-gartner-hype-cycle-identifies-top-ai-innovations-in-2025)、[Gartner 推論コスト予測](https://www.gartner.com/en/newsroom/press-releases/2026-03-25-gartner-predicts-that-by-2030-performing-inference-on-an-llm-with-1-trillion-parameters-will-cost-genai-providers-over-90-percent-less-than-in-2025)（発行: 2026年3月）

## B. 技術スタックの構成要素

### 全体像（7層アーキテクチャ）

```
┌─────────────────────────────────────────┐
│  インターフェース層（UI・API）             │ ← チャットUI / REST API / Webhook
├─────────────────────────────────────────┤
│  エージェントフレームワーク層              │ ← LangGraph / CrewAI / AutoGen
├─────────────────────────────────────────┤
│  RAG / ナレッジ層                        │ ← Qdrant / Weaviate + 埋め込みモデル
├─────────────────────────────────────────┤
│  推論エンジン層                           │ ← vLLM / SGLang / Ollama
├─────────────────────────────────────────┤
│  基盤モデル層                             │ ← Llama 3.3 / Qwen3 / Swallow 70B
├─────────────────────────────────────────┤
│  オーケストレーション・監視層              │ ← Kubernetes / Prometheus / LangSmith
├─────────────────────────────────────────┤
│  ハードウェア層                           │ ← NVIDIA GPU / NVMe SSD / 10Gbps NW
└─────────────────────────────────────────┘
```

### ハードウェア層（GPU/NPU、サーバー構成）

モデルサイズ別のGPU要件（量子化AWQ/GPTQ適用時）:

| モデルサイズ | 推奨GPU | 必要VRAM | 用途例 |
|------------|--------|---------|-------|
| 1B〜3B（SLM） | RTX 3060 / RTX 4060 | 6GB以上 | エッジ、リアルタイム処理 |
| 7B〜13B | RTX 3080 / RTX 4070 / RTX 4090 | 12〜24GB | 汎用RAG、社内チャットBot |
| 30B〜70B | RTX 4090 (×2〜4) / A100 40GB | 24〜80GB | 高度な推論、要約・分析 |
| 70B以上 / MoE | A100 80GB / H100 (×2以上) | 80GB以上（マルチGPU） | 高精度エージェント |

サーバー構成の基本要件:
- CPU: 高コア数（16〜64コア、GPU転送ボトルネックを防ぐ）
- ストレージ: NVMe SSD 2TB以上（モデルウェイト + データ格納）
- ネットワーク: 10Gbps以上（マルチユーザー対応）
- 冷却: データセンターグレードの空冷または水冷

出典: [OTTOSERVER TECHブログ GPU選定ガイド](https://www.pcserver1.jp/blog/archives/10630)（2025年）、[digital-base.co.jp](https://digital-base.co.jp/posts/ローカルLLM向けモデルごとのハードウェアの選び方)（2025年）

### 推論エンジン層

| エンジン | 主な用途 | 性能（Llama 3.1 8B / RTX 4090 / 10並列） | 特徴 |
|---------|---------|----------------------------------------|------|
| **vLLM** | 本番環境 | 800 tokens/sec（10並列） | PagedAttentionで高スループット。OpenAI互換API。本番の実質標準 |
| **SGLang** | 本番・構造化出力 | TGIより高速。RadixAttentionで最大26,000 input tokens/sec/GPU | RadixAttention・構造化出力が強力。a16z助成取得済み |
| **TGI（Text Generation Inference）** | 既存環境移行 | 500 tokens/sec（10並列） | 2025年12月にメンテナンスモード移行。新規採用は非推奨 |
| **Ollama** | 開発・検証 | 65 tokens/sec（単一ユーザー） | セットアップが最も簡単。本番用途には不向き |
| **llama.cpp** | CPU/エッジ | CPUでも動作可 | 量子化に強い。GPU不要の環境向け |

推奨方針: 新規本番構築は **vLLM または SGLang**。開発検証は **Ollama**。

出典: [ITECS - vLLM vs Ollama vs TensorRT-LLM](https://itecsonline.com/post/vllm-vs-ollama-vs-llama.cpp-vs-tgi-vs-tensort)（2025年）、[Ollama vs vLLM vs TGI Benchmark 2026](https://medium.com/@anupkawarase.akz/ollama-vs-vllm-vs-tgi-local-llm-serving-benchmark-2026-ba7d8474fea7)（2026年4月）

### エージェントフレームワーク層

| フレームワーク | 主な強み | 自社ホスティング適性 | 習得難易度 | 推奨度 |
|-------------|---------|-------------------|-----------|-------|
| **LangChain / LangGraph** | 最も広い統合、グラフ型ワークフロー、監査・コンプライアンス対応 | 高 | 中 | ★★★★★ |
| **LlamaIndex** | RAG特化。データ取り込み〜検索〜回答生成を一貫サポート | 高 | 中 | ★★★★ |
| **CrewAI** | ロールベースのマルチエージェント。直感的なチーム設計 | 高 | 易 | ★★★★ |
| **AutoGen (Microsoft)** | 会話型マルチエージェント。複雑な対話フローに強い | 高 | 中 | ★★★ |
| **Flowise / Langflow** | ノーコード・ビジュアル設計。エンジニア以外でも操作可 | 高 | 易 | ★★★（PoC向け）|
| **DSPy** | プログラマティックなプロンプト最適化。SGLangと統合可能 | 高 | 難 | ★★★（研究・最適化向け）|

**受託スタートアップとしての優先習得**: LangGraph（複雑なワークフロー）+ LlamaIndex（RAG）の組み合わせが最も汎用性が高い。

出典: [Turing - Top AI Agent Frameworks 2026](https://www.turing.com/resources/ai-agent-frameworks)、[getmaxim.ai](https://www.getmaxim.ai/articles/top-5-ai-agent-frameworks-in-2025-a-practical-guide-for-ai-builders/)（2025年）

### RAG / ナレッジ層

ベクターデータベース比較（オンプレ用途）:

| DB | ライセンス | 特徴 | 自社ホスティング | 推奨用途 |
|----|-----------|------|----------------|---------|
| **Qdrant** | Apache 2.0 | Rust製で高速。メモリ効率優秀。Docker対応 | 容易 | 本番RAG。PoC〜本番まで使える |
| **Weaviate** | BSD-3 | ハイブリッド検索（ベクター+全文）。GraphQL API | 中程度（学習コスト） | 複合検索が必要なエンタープライズ |

| **Chroma** | Apache 2.0 | Python-firstで最も簡単 | 容易 | PoC・開発環境。本番は移行推奨 |
| **pgvector** | PostgreSQL拡張 | 既存PostgreSQLに追加可能 | 容易 | 既存DBインフラ流用 |

埋め込みモデル（日本語）: `intfloat/multilingual-e5-large`、東北大 `tohoku-nlp/bert-base-japanese`（8,192トークン対応版）が実績あり。

### GPU調達の現状（2025年）

- **H100（80GB SXM）**: 日本での定価は約473万円（税込）。市場価格は33,000〜40,000ドル相当
- **A100（80GB）**: 約150〜170万円相当（PCIeモデル）
- **RTX 4090（24GB）**: 約25〜35万円（民生品。中小規模受託に最適）
- **調達リードタイム**: エンタープライズGPUは平均5〜6ヶ月待ちが発生
- **代替戦略**: 初期はクラウドGPU（Runpod・Vast.ai・さくらのクラウド等）でPoC、受注確定後にオンプレ調達が現実的

コスト優位性: オンプレLLMはクラウドAPIに比べ最大18倍のトークンコスト削減が可能。H100単体で月350〜500時間フル稼働の場合、1年で元が取れる計算。
