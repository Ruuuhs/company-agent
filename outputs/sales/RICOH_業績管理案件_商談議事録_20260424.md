## 4. 現状（As-Is）の業務・システム構成

### 利用中システム一覧

| システム名 | カテゴリ | 主な用途 | 現状の課題 |
|-----------|---------|---------|-----------|
| ZAC | 案件管理・販売管理 | 見込み管理、外部発注管理 | Power BIへの見込み追加が手動。案件単位の可視化はできているが自動連携なし |
| CUBIC | 財務会計（RICOH独自） | 財務会計全般 | 他システムとの自動連携なし |
| Loglass | 計画・実績・見込み管理 | 予算計画・実績・見込みの管理 | ZACからの見込みデータ自動入力が未実現 |
| Power BI | BIツール・可視化 | 最終的な数値の可視化・レポーティング | 更新が1日3回まで、その場でのリアルタイム修正不可 |
| SAP | ERP | 基幹システム（基本はSAP） | エクセル併用が常態化しており、SAPへの統合が不完全 |
| エクセル | 表計算 | 予算管理・経費予算管理・人事データ連携 | 脱却を強く希望。担当者依存・属人的運用 |
| DF（起案書システム） | ワークフロー | 起案・稟議 | 予算管理システムと分断。手動での転記が発生 |
| ジャストDB | データベース | 同時接続型DB | 詳細不明（※要確認） |
| 給与システム（RICOHグループ共通） | 給与・賞与 | 給与・賞与計算 | 入力は手動。自動取り込みの仕組みが一部あるが不完全 |

### 業務上のペイン（痛みポイント）

**最大の痛み**
> 「予算と見込みが一番手がかかる」

- 各システムが独立しており、**自動連携がゼロ**。データの転記・集計がすべて手動。
- 予算管理はエクセル、起案（DF）は別システム、という**二重管理**が常態化。
- Power BIは**1日3回しか更新できず**、経営判断に必要なリアルタイム性が担保されていない。
- ZACの見込みデータをLoglassに手動で入力し直す作業が毎回発生している。
- エクセルで**「粘土（※原文ママ、「年度」と推定修正）」単位の予算を上期・下期・月割で管理**しており、修正コストが高い。
- 業績部からの**異動者が多く**、属人的な業務知識の引き継ぎ問題が内在している可能性あり（※要確認）。

**その他のペイン**
- ABCランクで案件に優先度を付けているが、高優先度案件（AB）が早期に終わったとしても低優先度（C）への切り替えが迅速に行えていない。
- 人事部のデータ（給与・賞与等）はエクセルでRICOHに送付しており、基幹システムとの連携が不完全。

## 8. 提案の方向性（仮説）

### 提案で押さえるべきキーポイント

| ポイント | 内容 |
|---------|------|
| **ゴール逆算型の提案** | 2030年42%削減から逆算したロードマップを示し、「今なぜ業績管理から始めるべきか」を論理的に説明する |
| **3ヶ月の成果の明確化** | ツール選定・計画策定の成果物を具体的に定義し、発注側が判断できる状態にする |
| **フルスペック人材の提示** | 業務理解・アーキテクト・指導能力を持つ人材のプロフィールを具体的に提示する |
| **脱エクセル・自動化の具体像** | ZAC→Loglass→Power BIのデータフロー自動化の構成案をビジュアルで示す |
| **内製化支援の明示** | RICOHの担当者への知識移転・指導をスコープに明示し、外部依存を続けない姿勢を示す |
| **横展開の提案** | 業績管理を皮切りに、4事業展開・他部門（人事・コーポレート）への展開シナリオも添える |

### 競合・既存ベンダーとの関係性

- ZAC・CUBIC・Loglass・SAPはすでに導入済みの既存ベンダー製品。**既存システムを活かしながら連携させる**ポジショニングを取ることで、既存ベンダーとの競合を避けられる。
- 「既存のローコードはなんとかなる」という発言から、既存IT部門との協調が必要。**外部から来て既存を否定するスタンス**は禁物。
- 差別化軸は「業務理解 × アーキテクト設計 × 指導・内製化支援」の三位一体であり、システム導入ベンダーとは異なるポジションを取ること。
