# 技術調査レポート：Gitリポジトリにおける共有ファイルとローカル専用ファイルの分離パターン

**作成日**: 2026-04-14  
**作成部門**: リサーチ部  
**調査対象リポジトリ**: company-agent  
**ステータス**: 完了

---

## 背景と目的

`company-agent` リポジトリの `context/` フォルダ（AIの記憶ファイル群）を、リモートリポジトリに push せず各自のローカルにのみ保持したい。リポジトリ本体（`agents/`, `guidelines/`, `outputs/`）は引き続き git 管理を継続する。

**現在の状態（2026-04-14 時点）**:
- `context/` 配下の全ファイルが既に git 追跡済み（`git ls-files context/` で確認）
- `.gitignore` に `context/` の記載なし
- 追跡済みファイルを除外するには `git rm --cached` が必要

---

## 1. 手法比較表

| 手法 | 概要 | 難易度 | push 誤爆リスク | 新メンバー対応 | Claude Code 対応 |
|------|------|--------|----------------|--------------|-----------------|
| **手法1** `.gitignore` に `context/` 追加 | `.gitignore` に記載 + 追跡解除 | ★☆☆ 低 | 低（一度設定すれば全員に効く） | 良好（clone 後に自動適用） | ◎ 問題なし |
| **手法2** `.git/info/exclude` | ローカル専用 gitignore に記載 | ★☆☆ 低 | 低（ローカルのみ） | 要注意（各自で設定必要） | ◎ 問題なし |
| **手法3** シンボリックリンク | 実体を外部に置きリポジトリからリンク | ★★★ 高 | 低（リンク自体を除外） | 困難（各自が手動でリンク作成） | ◎ パス参照は透過的 |
| **手法4** `context.template/` + `setup.sh` | テンプレートを管理しローカル生成 | ★★☆ 中 | 低（`context/` を除外） | 優秀（`./setup.sh` 一発） | ◎ 問題なし |
| **手法5** `~/.claude/CLAUDE.md` 活用 | 個人設定をグローバル CLAUDE.md に記述 | ★☆☆ 低 | ― （git 管理外） | 要注意（各自で設定必要） | ◎ Claude Code が両方読む |

---

## 2. 各手法の詳細

### 手法1: `.gitignore` に `context/` を追加

**仕組み**  
`.gitignore` に `context/` を追記することで git の追跡・push 対象から除外する。既に追跡済みのファイルは `git rm --cached` で追跡解除が必要。

**メリット**
- 設定がリポジトリに含まれるため、全メンバーに自動適用される
- 実装が最もシンプル
- ローカルのファイルは削除されない（参照可能なまま）

**デメリット**
- 既に追跡済みの場合、`git rm --cached` を一度実行する必要がある
- チームメンバー全員がそれぞれ `git rm --cached` を実行するか、または自分が実行した後に他メンバーが pull する必要がある

**難易度**: 低

**具体的なコマンド**
```bash
# .gitignore に追記
echo "context/" >> .gitignore

# 既に追跡済みのファイルを追跡解除（ローカルファイルは残る）
git rm --cached -r context/

# コミット
git add .gitignore
git commit -m "chore: context/ をgit管理対象から除外"
git push
```

---

### 手法2: `.git/info/exclude`（ローカル専用 gitignore）

**仕組み**  
`.git/info/exclude` は `.gitignore` と同じ書式だが、リモートに共有されない。このファイルへの記述は自分のローカル環境にのみ効果を持つ。

**メリット**
- `.gitignore` 自体を変更しないため、リポジトリの状態に影響しない
- 他のメンバーの設定に干渉しない

**デメリット**
- 新しいメンバーがリポジトリを clone しても自動設定されない（各自が手動設定）
- チーム規模が大きくなるほど管理が難しくなる
- onboarding ドキュメントに手順を明記しないと忘れられやすい

**難易度**: 低

**具体的な操作**
```bash
# .git/info/exclude を編集（nano, vim など任意のエディタで）
echo "context/" >> /path/to/repo/.git/info/exclude

# 追跡解除（必要な場合）
git rm --cached -r context/
```

---

### 手法3: `context/` をリポジトリ外に出しシンボリックリンクで繋ぐ

**仕組み**  
ファイルの実体を `~/.company-agent/context/` などリポジトリ外に置き、リポジトリ内の `context/` はそこへのシンボリックリンクとする。`.gitignore` でシンボリックリンク自体を除外する。

**メリット**
- `context/` の実体がリポジトリから完全に分離される
- バックアップ戦略を独立して設計できる
- 複数リポジトリで同じコンテキストを共有できる（応用）

**デメリット**
- 新メンバーは自分でディレクトリを作成してシンボリックリンクを張る必要がある
- Windows 環境では管理者権限が必要な場合がある
- CI/CD 環境での扱いに注意が必要

**難易度**: 高

**具体的なコマンド**
```bash
# 実体の保存先を作成
mkdir -p ~/.company-agent/context

# 既存の context/ を移動
cp -r /path/to/repo/context/* ~/.company-agent/context/
git rm -r context/

# シンボリックリンクを作成
ln -s ~/.company-agent/context /path/to/repo/context

# .gitignore に追記
echo "context" >> .gitignore

git add .gitignore
git commit -m "chore: context/ をシンボリックリンク化し除外"
```

---

### 手法4: `context.template/` をgit管理し `context/` はローカル生成

**仕組み**  
`context.template/` フォルダに初期ファイルのひな形を git 管理する。`setup.sh` スクリプトで `context.template/` を `context/` にコピーしてローカル生成。`context/` は `.gitignore` で除外。

**メリット**
- 新メンバーが `./setup.sh` を実行するだけで環境構築できる
- テンプレート（初期状態）はチーム全体で共有できる
- ローカルの `context/` は各自が自由にカスタマイズ可能

**デメリット**
- `context.template/` と `context/` の二重管理が発生する
- テンプレートの更新を `context/` に反映する仕組みが別途必要

**難易度**: 中

**具体的なファイル構成**
```
company-agent/
├── context.template/        # git管理（ひな形）
│   ├── README.md
│   ├── activeContext.md
│   ├── company-state.md
│   └── ...
├── context/                 # .gitignore で除外（ローカル専用）
│   └── ...（setup.sh で生成）
├── setup.sh                 # git管理
└── .gitignore               # context/ を除外
```

**setup.sh の内容例**
```bash
#!/bin/bash
set -e

if [ -d "context" ]; then
  echo "context/ already exists. Skipping."
else
  echo "Creating context/ from context.template/ ..."
  cp -r context.template/ context/
  echo "Done. context/ is ready."
fi
```

**.gitignore への追記**
```
context/
```

---

### 手法5: `~/.claude/CLAUDE.md`（グローバル CLAUDE.md）を活用

**仕組み**  
Claude Code は起動時に `~/.claude/CLAUDE.md`（ユーザーホームの設定）とプロジェクトの `CLAUDE.md` の両方を読み込む。個人固有のコンテキストや状態を `~/.claude/CLAUDE.md` に記述することで、リポジトリ側の `CLAUDE.md` には書かない設計が可能。

**メリット**
- git 管理が不要（ファイルはホームディレクトリに存在）
- 複数プロジェクトをまたいで個人コンテキストを共有できる
- 設定が完全に個人管理

**デメリット**
- `context/` フォルダ丸ごとの分離には不向き（主に CLAUDE.md 一ファイルの話）
- チームの共有コンテキスト（会社状態・意思決定ログ等）には使えない
- マシン移行時に手動でコピーが必要

**難易度**: 低

**ファイルの場所**
```
~/.claude/CLAUDE.md   # 個人のグローバル設定（git管理外）
```

## 3. このリポジトリへの推奨案

### 推奨: 手法1（`.gitignore` 追加）+ 手法4（テンプレート）の組み合わせ

**理由**
- `context/` は既に git 追跡済みのため、まず追跡解除が必要（手法1が必須）
- 新メンバーがゼロから環境構築できるよう、テンプレートと `setup.sh` を整備する（手法4）
- これにより「全員に除外が自動適用」「新メンバーの onboarding も簡単」の両立が実現する

---

### 移行手順（現在の状態からの具体的な手順）

**前提**: `context/` は現在 git 追跡済み（`git ls-files context/` で確認済み）

#### ステップ 1: テンプレートフォルダを作成

```bash
# context/ をテンプレートとしてコピー
cp -r /home/user/company-agent/context /home/user/company-agent/context.template
```

#### ステップ 2: `setup.sh` を作成

```bash
cat > /home/user/company-agent/setup.sh << 'EOF'
#!/bin/bash
# company-agent ローカル環境セットアップスクリプト
set -e

echo "=== company-agent セットアップ ==="

# context/ フォルダの初期化
if [ -d "context" ]; then
  echo "[SKIP] context/ は既に存在します。スキップします。"
else
  echo "[INIT] context.template/ から context/ を生成します..."
  cp -r context.template/ context/
  echo "[OK]   context/ を作成しました。"
fi

echo "=== セットアップ完了 ==="
EOF

chmod +x /home/user/company-agent/setup.sh
```

#### ステップ 3: `.gitignore` に `context/` を追加

```bash
echo "" >> /home/user/company-agent/.gitignore
echo "# AIの記憶ファイル（ローカル専用・個人管理）" >> /home/user/company-agent/.gitignore
echo "context/" >> /home/user/company-agent/.gitignore
```

#### ステップ 4: git 追跡を解除（ローカルファイルは残す）

```bash
cd /home/user/company-agent
git rm --cached -r context/
```

#### ステップ 5: コミット・プッシュ

```bash
cd /home/user/company-agent
git add .gitignore context.template/ setup.sh
git commit -m "chore: context/ をローカル専用化、テンプレートとsetup.shを追加"
git push
```

#### ステップ 6: 各メンバーへの周知

他のメンバーは `git pull` 後に以下を実行：

```bash
# 既存の context/ が追跡解除されるが、ローカルファイルは残っているため問題なし
git pull

# もし context/ が存在しない場合は setup.sh で再生成
./setup.sh
```

---

### 移行後の運用フロー

```
新メンバーの参加時:
  1. git clone <リポジトリURL>
  2. ./setup.sh  ← これだけで context/ がローカルに生成される

既存メンバーの運用:
  - context/ への変更は git に入らない（push 不可）
  - context.template/ の更新がある場合は手動で context/ に反映する
  
Claude Code の動作:
  - CLAUDE.md の手順通り context/ を参照 → 問題なし（ローカルに存在するため）
```

## まとめ

| 観点 | 結論 |
|------|------|
| 最優先の手法 | 手法1（`.gitignore`）必須（既存追跡ファイルの解除のため） |
| 組み合わせ推奨 | 手法4（テンプレート + setup.sh）で新メンバー対応を強化 |
| 手法2 の位置付け | 個人の追加ルールに使う補助的な手段として有効 |
| 手法3 の位置付け | このユースケースではオーバーエンジニアリング |
| 手法5 の位置付け | `context/` 分離とは別の用途（個人の CLAUDE 設定）向け |
