## エグゼクティブサマリー

「共有リポジトリ＋個人ローカル記憶の分離」には**5つの主要手法**が存在する。このリポジトリ（company-agent）への推奨は以下の組み合わせ：

> **推奨: 手法A（.gitignore除外）＋手法D（context.template/パターン）の組み合わせ**
>
> - `context/` を `.gitignore` に追加してgit管理から外す
> - `context.template/` をgit管理して初期ファイルのひな形を提供
> - `setup.sh` で新メンバーのオンボーディングを自動化

## 2. 各手法の詳細

### 手法A: .gitignore に context/ を追加（★★★★★ 推奨）

**仕組み**: `.gitignore` に `context/` を記載することで、Gitがこのフォルダを追跡対象外にする。

**メリット**:
- 最もシンプル。1行追加するだけ
- Claude Codeがリポジトリ内の `context/` パスで参照できる（パス変更不要）
- プッシュ誤爆が完全になくなる

**デメリット**:
- **現在すでにgit管理されているファイルは、.gitignoreに追加しただけでは除外されない**
- `git rm --cached` での追跡解除が必要（移行コストあり）

**移行手順（現在のリポジトリへの適用）**:
```bash
# Step 1: .gitignore に context/ を追加（後述のsetup.shと組み合わせ）
echo "context/" >> .gitignore

# Step 2: Gitの追跡キャッシュから除外（ファイル自体はローカルに残る）
git rm --cached -r context/

# Step 3: コミット
git add .gitignore
git commit -m "chore: context/をgit管理から除外（個人ローカル専用に変更）"

# Step 4: プッシュ
git push
```

> ⚠️ **重要**: Step 2実行後、リモートリポジトリの `context/` フォルダは削除されます。しかし**ローカルのファイルは消えません**。他のメンバーがpullすると、そのメンバーのローカルからも `context/` が削除されます。移行前にバックアップを取ること。

---

### 手法B: .git/info/exclude（ローカル専用 .gitignore）

**仕組み**: `.git/info/exclude` はローカルマシンだけに存在する除外ルールファイル。リモートに一切反映されない。

```bash
# 書き方（.gitignoreと同じ書式）
echo "context/" >> .git/info/exclude
```

**メリット**: リモートの `.gitignore` を変更せずに個人だけで除外できる
**デメリット**: `clone` するたびに毎回手動設定が必要。自動化できない。チームで統一しにくい

**適用場面**: `.gitignore` を変更したくない（組織の方針等）場合の個人対処として

---

### 手法C: シンボリックリンク

**仕組み**: 実体ファイルをリポジトリ外（`~/.company-agent/context/`）に置き、リポジトリ内の `context/` はシンボリックリンク（ショートカット）にする。

```bash
# 実体の作成
mkdir -p ~/.company-agent/context

# リポジトリ内のcontext/を削除してシンボリックリンクに置き換え
rm -rf /path/to/company-agent/context
ln -s ~/.company-agent/context /path/to/company-agent/context

# .gitignoreに追加（シンボリックリンク自体も除外）
echo "context" >> .gitignore
```

**メリット**: 実体が完全にリポジトリ外。バックアップも独立
**デメリット**: Windowsではシンボリックリンクの動作が異なる。設定が複雑

---

### 手法D: context.template/ パターン（★★★★★ 推奨・手法Aと組み合わせ）

**仕組み**: 
- `context.template/` フォルダをgit管理（初期ファイルのひな形）
- `context/` はgit管理外（.gitignore）
- `setup.sh` を実行すると `context.template/` を `context/` にコピーしてローカル生成

**フォルダ構成**:
```
company-agent/
├── context/              # .gitignoreで除外（各自のローカル専用）
│   ├── company-state.md
│   ├── activeContext.md
│   └── ...
├── context.template/     # git管理（初期ファイルのひな形）
│   ├── company-state.md  # 空のテンプレート
│   ├── activeContext.md  # 空のテンプレート
│   └── README.md         # 使い方説明
└── setup.sh              # 初回セットアップスクリプト
```

**メリット**: 
- 新メンバーが `./setup.sh` を実行するだけで `context/` が自動生成される
- テンプレートをgitで管理でき、ひな形のアップデートも共有できる
- Claude Codeのパスは変わらず `context/` を参照できる

---

### 手法E: Gitサブモジュール

**仕組み**: `context/` を独立したprivateリポジトリとして管理し、メインリポジトリに組み込む。

```bash
# 各メンバーが自分専用のprivate repoを作成して登録
git submodule add https://github.com/username/my-company-agent-context context/
```

**メリット**: 完全に分離。個人のcontextをバックアップ・バージョン管理できる
**デメリット**: 設定が複雑。Gitに慣れていないメンバーには難しい。毎回 `git submodule update` が必要

## 3. Claude Code固有の機能：CLAUDE.mdの階層

Claude Codeは以下の順で CLAUDE.md を読み込む（すべて同時に有効）：

```
1. ~/.claude/CLAUDE.md         # グローバル（ユーザー個人の設定）
2. ~/company-agent/CLAUDE.md   # プロジェクト（リポジトリ共有）
3. ~/company-agent/subdir/CLAUDE.md  # サブフォルダ（あれば）
```

**活用法**: 
- `~/.claude/CLAUDE.md` に「個人の文脈・好み」を書く → リモートに反映されない
- `プロジェクト/CLAUDE.md` に「チーム共通のルール」を書く → git管理される

例：`~/.claude/CLAUDE.md` に以下を書くと個人設定として機能する：
```markdown
# 個人設定（ローカル専用）
私の名前は〇〇です。context/フォルダの読み込みを最優先にしてください。
```

### Obsidian（チームVault）
- `.obsidian/` フォルダ（プラグイン設定等）は `.gitignore` で除外が推奨
- チームで共有するノートだけgit管理し、個人のワークスペース設定は除外

### dotfiles の `.env.local` パターン
```

.env.local      # .gitignoreで除外（個人の実際の値）
```
→ **`context.template/` + `context/`** はこのパターンの直接応用

## 5. このリポジトリへの推奨実装

### 推奨構成（手法A + D の組み合わせ）

```
company-agent/
├── .gitignore              # context/ を除外（追加が必要）
├── setup.sh                # 新メンバー用セットアップスクリプト（新規作成）
├── CLAUDE.md               # git管理（チーム共有）
├── context/                # .gitignore対象（各自のローカル専用）
│   ├── company-state.md
│   ├── activeContext.md
│   ├── decisions-log.md
│   ├── ongoing-projects.md
│   └── session-log.md
├── context.template/       # git管理（新メンバー向けひな形）
│   ├── company-state.md    # 空の初期テンプレート
│   ├── activeContext.md
│   ├── decisions-log.md
│   ├── ongoing-projects.md
│   ├── session-log.md
│   └── README.md
├── agents/                 # git管理
├── guidelines/             # git管理
├── outputs/                # git管理
└── templates/              # git管理
```

### setup.sh の内容（新規作成）

```bash
#!/bin/bash
# company-agent セットアップスクリプト
# 新しいメンバーがclone後に一度だけ実行する

echo "=== company-agent セットアップ開始 ==="

# context/ フォルダが存在しない場合、テンプレートからコピー
if [ ! -d "context" ]; then
  echo "context/ フォルダを context.template/ から生成します..."
  cp -r context.template context
  echo "✅ context/ を生成しました"
else
  echo "ℹ️  context/ は既に存在します。スキップします"
fi

echo ""
echo "=== セットアップ完了 ==="
echo "次のステップ:"
echo "  1. context/company-state.md を開いて会社情報を入力してください"
echo "  2. context/activeContext.md を今日のフォーカスで更新してください"
echo "  3. Claude Code で 'claude' コマンドを実行してください"
```

### 移行手順（現在のcontext/をgit管理から外す）

```bash
# 1. context.template/ を作成（現在のcontext/をひな形としてコピー）
cp -r context context.template

# 2. context.template/ の中身を空のテンプレートに整形
#    （個人情報・意思決定ログ等を削除し、空の状態にする）

# 3. .gitignore に context/ を追加
echo "" >> .gitignore
echo "# 個人ローカル専用（各自のAI記憶ファイル）" >> .gitignore
echo "context/" >> .gitignore

# 4. Gitの追跡キャッシュから context/ を除外
git rm --cached -r context/

# 5. setup.sh を作成・実行権限付与
chmod +x setup.sh

# 6. コミット
git add context.template/ setup.sh .gitignore
git commit -m "feat: context/をローカル専用に変更・context.template/とsetup.shを追加"

# 7. プッシュ
git push
```

## 7. リスクと注意事項

| リスク | 内容 | 対処法 |
|--------|------|--------|
| context/のバックアップ消失 | ローカルにしかないため、PC故障時に消える | 個人でクラウドバックアップ（iCloud/Dropbox等）に入れるか、private branchで定期コミット |
| 移行時に他メンバーのcontext/が消える | git rm --cached後にpullすると消える | 移行前に全メンバーにバックアップ指示を出す |
| context.template/が古くなる | テンプレートと実際のcontextが乖離 | context.template/を更新したら全メンバーに通知し、差分を手動マージ |
