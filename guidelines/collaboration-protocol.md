# 連携プロトコル

## エージェント間連携の基本原則

1. チーフ（CLAUDE.md）が全連携の起点となる
2. エージェント同士が直接やり取りするのではなく、必ずチーフを通す
3. 各エージェントは自分の専門領域に集中する
4. 並列作業の結果はチーフが統合する

## 連携が必要な典型パターン

### パターン1：戦略 × データ
```
「来期の事業戦略を立てて」
  → 戦略立案者（経営企画部）: 戦略立案
  → KPIアナリスト（データ分析部）: 実績データ分析
  → チーフが統合してレポート
```

### パターン2：コンテンツ × マーケ
```
「YouTubeの企画とプロモーション計画を作って」
  → YouTube企画者（コンテンツ制作部）: 企画・台本
  → SNSライター（マーケティング部）: 拡散・プロモーション計画
  → チーフが統合
```

### パターン3：採用 × 経営管理
```
「新しいポジションを採用したい」
  → 採用マネージャー（人事部）: 求人票・選考フロー
  → 財務コントローラー（経営管理部）: 人件費予算チェック
  → チーフが統合
```

## 引き継ぎフォーマット

エージェント間でファイルを引き継ぐ場合は以下の形式で記録する：

```markdown
## 引き継ぎ情報
- 送り元: （エージェント名）
- 受け取り先: （エージェント名）
- 引き継ぎ日時: YYYY-MM-DD HH:MM
- 内容の概要: （1〜2文）
- ファイルパス: （関連ファイルのパス）
- 注意事項: （引き継ぎ先が注意すべきこと）
```

## 品質レビューの連携

大型タスクでは生成者と評価者を分離する：

| タスク | 生成者 | 評価者 |
|--------|--------|--------|
| YouTube台本 | 台本ライター | 教材設計者（教育系）/ YouTube企画者（通常） |
| X投稿案 | SNSライター | コピーライター |
| 提案書 | 営業サポート | 収益設計者（価格観点） |
| 戦略レポート | 戦略立案者 | 競合アナリスト |

## コンテキストリセットのタイミング

以下のフェーズ移行時にコンテキストをリセットし、新しいエージェントに引き継ぐ：

1. 情報収集フェーズ → 分析フェーズ
2. ドラフト作成フェーズ → レビューフェーズ
3. レビューフェーズ → 最終化フェーズ

各フェーズの成果物は必ず `outputs/` の適切なサブフォルダにファイルとして保存してから引き継ぐこと（保存先は `guidelines/output-standards.md` の「部門別の保存先早見表」を参照）。

## 部門横断の主要連携マップ

```
戦略立案者
  ↕ 実績数値     ↕ 市場データ
KPIアナリスト   市場調査員
  ↕ 収益KPI      ↕ VOC
財務コントローラー  事業企画者
```
