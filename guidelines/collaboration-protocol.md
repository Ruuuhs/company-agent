# 連携プロトコル

## エージェント間連携の基本原則

1. チーフ（CLAUDE.md）が全連携の起点となる
2. エージェント同士が直接やり取りするのではなく、必ずチーフを通す
3. 各エージェントは自分の専門領域に集中する
4. 並列作業の結果はチーフが統合する

## 連携が必要な典型パターン

### パターン1：戦略 × データ
```
「来期の事業戦略を立てて」
  → 経営企画部（Haruto）: 戦略立案
  → データ分析部（Shun）: 実績データ分析
  → チーフが統合してレポート
```

### パターン2：コンテンツ × マーケ
```
「YouTubeの企画とプロモーション計画を作って」
  → コンテンツ制作部（Eito）: 企画・台本
  → マーケティング部（Sho）: 拡散・プロモーション計画
  → チーフが統合
```

### パターン3：採用 × 経営管理
```
「新しいポジションを採用したい」
  → 人事部（Minato）: 求人票・選考フロー
  → 経営管理部（Kento）: 人件費予算チェック
  → チーフが統合
```

## 引き継ぎフォーマット

エージェント間でファイルを引き継ぐ場合は以下の形式で記録する：

```markdown
## 引き継ぎ情報
- 送り元: （エージェント名）
- 受け取り先: （エージェント名）
- 引き継ぎ日時: YYYY-MM-DD HH:MM
- 内容の概要: （1〜2文）
- ファイルパス: （関連ファイルのパス）
- 注意事項: （引き継ぎ先が注意すべきこと）
```

## 品質レビューの連携

大型タスクでは生成者と評価者を分離する：

| タスク | 生成者 | 評価者 |
|--------|--------|--------|
| YouTube台本 | コンテンツ制作部（Eito/Shiori） | コンテンツ制作部（Itsuki） |
| X投稿案 | マーケティング部（Sho） | マーケティング部（Takumi） |
| 提案書 | 営業部（Honoka） | 営業部（Ryota） |
| 戦略レポート | 経営企画部（Haruto） | 経営企画部（Kaito） |

## コンテキストリセットのタイミング

以下のフェーズ移行時にコンテキストをリセットし、新しいエージェントに引き継ぐ：

1. 情報収集フェーズ → 分析フェーズ
2. ドラフト作成フェーズ → レビューフェーズ
3. レビューフェーズ → 最終化フェーズ

各フェーズの成果物は必ずファイルに保存してから引き継ぐこと。
