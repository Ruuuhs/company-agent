# Claude Code 仮想チーム構築ガイド

## 概要

Claude Codeを使い、10部門・40人の仮想社員チームを構築する手法のまとめ。  
コードは1行も書かない。必要なのは「自分の会社でどんな仕事が発生するか」を整理して言葉にすることだけ。

---

## なぜAIを「社員化」するのか

### Claude Codeは「チャット」ではなく「実務遂行者」

普通のAIチャットは聞いたことに答えるだけ。  
Claude Codeは違う。

- PC上のファイルを直接読み書きできる
- Webで調べ物もできる
- スクリプトを動かすこともできる

会社の情報をファイルに書いておけば、毎回説明しなくても最初から知っている状態で仕事してくれる。

### なぜ「AIの役割」を分けるのか

> 「なんでもできる人は、何をやっても70点の人になりやすい」——これはAIでも起きる。

1つのAIにマーケの指示も経理の指示も全部覚えさせると、情報が散らかる。  
性質が全く違うものが1つのファイルに同居していると、AIはどっちの文脈で動けばいいか迷う。

Claude Codeには、自分の中から別のClaude Codeを立ち上げる機能（Agent tool）がある。  
この仕組みを使って、マーケ担当にはマーケの指示だけ、経理担当には経理の指示だけを渡す。

**さらに、1回の指示で複数のAI社員が同時に動く。**

「来期の戦略考えて」と言えば、戦略担当・競合分析担当・データ分析担当が同時に動き出して、結果をまとめて報告してくれる。

## 構築手順

### ステップ1：業務の棚卸し

まず自分の業務を全部書き出す。

```
事業企画 / 事業戦略策定
YouTube企画＆出演
X運用
広報
経費確認
採用
受託案件の管理
M&A案件の評価
```

これをClaude Codeに渡すと、「漏れなくダブりなく」分類して部門に整理してくれる。

---

### ステップ2：エージェント定義の作成

各部門にエージェントを配置。各エージェントの `.md` ファイルには5つの要素を記述する。

| 要素 | 内容 |
|------|------|
| 役割 | 何を担当するか |
| 人格・トーン | どんな人格で振る舞うか |
| 参照guidelines | どの社内マニュアルを見るか |
| 連携先 | 誰と協働するか |
| 判断基準 | どこまで自分で判断し、どこから代表に確認するか |

**人格定義の例（経営企画部 Haruto）：**

> 冷静沈着で論理的。感情ではなくデータと構造で語る。「3つの選択肢があります」と常に複数案を提示する。大局観があり、細部より全体像を重視する。口癖は「構造的に整理すると〜」

人格・トーンまで定義すると出力の質が変わる。「戦略を考えて」と言ったとき、必ず「推奨案とその理由」をセットで出してくる。

---

### ステップ3：共通マニュアル（guidelines）の作成

全エージェントが参照する「社内マニュアル」。「入社時研修マニュアル」の役割を果たす。

```
guidelines/
├── company-overview.md        （会社概要）
├── ceo-style-guide.md         （代表のスタイル）
├── brand-guidelines.md        （ブランドガイドライン）
├── output-standards.md        （品質基準）
├── collaboration-protocol.md  （連携プロトコル）
├── reporting-standards.md     （報告基準）
├── research-protocol.md       （リサーチ手法）
├── escalation-rules.md        （エスカレーションルール）
├── security-policy.md         （セキュリティポリシー）
├── tools-manual.md            （ツール利用マニュアル）
├── philosophy.md              （代表の思想・価値観）
└── top-posts-reference.md     （過去の人気投稿データ）
```

**ブランドガイドラインの記述例：**

```
* 「弊社」ではなく「デイトラ」を使う
* 感嘆符の連続使用は禁止（「!!!」はNG）
* 競合の名指し批判をしない
* 「絶対稼げる」「必ず転職できる」など、無責任な言葉は使わない
```

このマニュアルは育てられる。「この表現はNGだな」と気づいたら1行追記するだけで、次から全エージェントに反映される。

> **guidelinesは仮想チームの「本体」と言っても過言ではない。**

---

### ステップ4：司令塔（CLAUDE.md）の作成

プロジェクトルートに置く `CLAUDE.md`。

チーフ（司令塔）の役割は3つだけ：

| 役割 | 内容 |
|------|------|
| プランニング | 曖昧な指示を受けたとき、まず要件を明確化する |
| ルーティング | 「これは誰の仕事か」を判断して、適切なエージェントを起動する |
| 統合 | 各エージェントの結果を1つのレポートにまとめる |

**重要：** `CLAUDE.md` に「自分でアウトプットを作成しない」「エージェントのロールプレイをしない」と明記する。

Claude Codeは指示が曖昧だと「自分で全部やろうとする」。それだと「1人の万能AI」に戻ってしまう。チーフには「あなたの役割は指示を振ること。自分では手を動かさない」と明確に伝える。

**並列処理のフロー例：**

```
僕が「来期の戦略考えて」と指示する
  ↓
チーフ（CLAUDE.md）が指示を分類
  ↓
Agent toolで3つのサブエージェントを【同時に】起動
  ├── Haruto（経営企画部）→ 戦略立案
  ├── Kaito（経営企画部）→ 競合分析
  └── Shun（データ分析部）→ 実績データ分析
  ↓
3人の結果をチーフが統合して、僕に報告
```

各エージェントは独立したコンテキストを持つため、Harutoが戦略を考えている間、Kaitoは競合調査に集中できる。お互いの思考が干渉しない。

---

### ステップ5：テンプレートの配置

各エージェントが使う出力テンプレートを用意する（全13種類）。

テンプレートがあると、エージェントが「何をどの形式で出力すべきか」に迷わない。出力の質が安定する。

---

## 設計原則（Anthropicのエンジニアリングブログより）

### CLAUDE.mdを軽量に保つ

AIには「注意力の予算（attention budget）」があり、不要な情報を入れるほど精度が落ちる。

- `CLAUDE.md`（司令塔）には最小限のルーティングルールだけを書く
- 部門ごとの細かい指示は `.claude/commands/` に分離する
- 必要な部門だけがオンデマンドでロードされるので、司令塔は軽い

### 作った人と評価する人を分ける

AIに自分の出力を評価させると、品質が低くても「素晴らしいです！」と返ってくる。

- Eitoが書いた台本はItsukiがレビューする
- ShoのX記事はTakumiが評価する

生成者と評価者を分離することで品質を担保する。

## 実際の使い方

### 例1：「来期の戦略考えて」

```
僕 → 「来期の戦略考えて」

チーフが自動で判断：
  → Haruto（経営企画部 / 戦略・企画）
  → Kaito（経営企画部 / 競合分析）
  → Shun（データ分析部 / 実績データ）
3名が同時に動き出す。

結果：
  Haruto → 3つの戦略案を提示
  Kaito  → 競合動向を整理
  Shun   → 過去2年分のKPIデータで裏付け
  → チーフが3つの出力を統合して報告
```

### 例2：「YouTubeのネタ出して」

```
僕 → 「YouTube撮りたいんだけどネタある？」

チーフが判断：
  → Eito（コンテンツ制作部 / YouTube全般）
1名を起動。

結果：
  過去の動画の視聴データとブランドガイドラインを踏まえて企画案を5つ提案
  各企画の台本構成まで一気に作成（代表の口調ガイドに沿って）
  サムネイルの方向性もブランドカラーに合わせて提案
```

### 例3：「この経費確認して」

```
僕 → 「今月の経費確認して」

チーフが判断：
  → Kento（経営管理部 / 経費）
1名を起動。

結果：
  経費チェックリストのテンプレートと前月の確認結果を参照して確認ポイントを整理
  不明な項目は「代表に確認が必要」と明記
```

## コピペで使えるプロンプト

> **注意：** 新しい空のフォルダで `claude` を起動してからこのプロンプトを実行する。既存の `CLAUDE.md` があるフォルダで実行すると、そちらのルールが優先されてしまう。

```
あなたはClaude Codeのエージェントシステム設計者です。
以下の情報をもとに、私の業務を支援する仮想チームを構築してください。

■ 私の情報
- 会社名: [あなたの会社名]
- 役職: [あなたの役職]
- 業務内容: [担当している業務を箇条書きで]
- 会社の事業内容: [一言で]
- 会社のミッション/ビジョン: [一言で]

■ やりたいこと
私の業務領域を漏れなくダブりなく分解して、以下の構成でClaude Codeの
エージェントシステムを構築してください。

1. CLAUDE.md（司令塔）
   - プロジェクトルートに配置
   - 私の指示を受け取り、最適なエージェントを判断して起動するルールを記述
   - ルーティングテーブルは最小限に。詳細は部門別スキルファイルに分離
   - できるだけ軽量に保つ（不要な情報はスキルファイルに外出しする）

2. agents/（部門別エージェント）
   - 業務を機能別に分解して部門を設計（目安: 5〜10部門）
   - 各部門に専門エージェントを配置（各部門1〜3名）
   - 「1つの専門領域は1人が担当する」設計を意識する
   - 各エージェントの.mdファイルに以下を記述:
     - 役割の定義
     - 人格・トーン
     - 参照すべきguidelines
     - 他エージェントとの連携ルール
     - 判断基準（どこまで自分で判断し、どこから確認するか）

3. .claude/commands/（部門ルーター）
   - 各部門のルーティング詳細をスラッシュコマンドとして分離
   - /strategy, /marketing のように部門ごとに1ファイル
   - 必要な部門だけオンデマンドでロードされるので、CLAUDE.mdが軽くなる

4. guidelines/（社内マニュアル）
   - 全エージェントが参照する業務マニュアルを作成（目安: 6〜12冊）
   - 「入社時研修マニュアル」レベルで、誰が読んでも同じ品質の仕事ができるように書く

5. templates/（出力テンプレート）
   - エージェントの出力フォーマットを統一するテンプレートを用意

■ 重要な設計方針
- 「1つのAIに全部やらせる」のではなく「専門家チーム」として設計する
- 各エージェントは明確に異なる人格・専門性・トーンを持つ
- CLAUDE.md（司令塔）は自分で作業せず、プランニング・ルーティング・統合だけ行う
- 複合タスクでは複数エージェントを並列起動する設計にする
- Agent tool（サブエージェント）で独立プロセスとして起動する設計にする
- 生成と評価を分離する（作った人と評価する人を別エージェントにする）
- 大型タスクではフェーズ分割してコンテキストをリセットする
  （各フェーズの成果物をファイルに出力し、次のフェーズは新しいエージェントがそのファイルを読んで作業する）

■ 出力形式
- 全ファイルを実際に作成してください（内容も省略せず書く）

それでは、上記の構成で全ファイルを作成してください。
```

## 使い込んで気づいたこと

### guidelinesは「育てるもの」

最初に作ったブランドガイドラインは20行くらい。使い込むうちに50行を超えた。

- 「この表現はNGだな」と気づくたびに追記する
- 「この言い回しはブランドっぽくていいな」と思ったらOK表現として追加する

使い込むほど、チーム全体の出力品質が上がっていく。

### 仮想チームは「完成」しない

最初は40人で作って、使いながら統合・追加を繰り返して、今は約20人。

最初から完璧を目指す必要はない。使いながら育てていく。それが仮想チームの本質。

毎日使いながら、マニュアルに1行追記する。エージェントの役割を微調整する。コマンドやスキルを1つ追加する。その積み重ねで、1ヶ月後には「自分の会社のことを本当に理解しているチーム」になっている。

> チャットの履歴は流れていくが、guidelinesに書いた知識は残り続ける。  
> 仮想チームは「作って終わり」ではなく、事業と一緒に育てていく相棒。
